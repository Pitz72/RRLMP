# 第 14 章 — 故障排除与常见问题

---

本章汇集 Runtime Live Machine Pro 日常使用中最常见的问题及其解决办法。每一节都描述症状、最可能的原因和解决步骤。

---

## 14.1 音频问题

### 计时器在走、VU meter 在动，却听不到声音

软件正在正确播放（信号存在于内部总线中），但没有抵达监听设备。

**按顺序检查：**

1. **主音量。** 页眉中的滑块是否为零？把它拉到 100%。
2. **输出设备。** 打开 设置 → *Audio & Mix*，查看选中的是哪个设备。Windows 与 macOS 在 USB 设备被断开又重连时可能改变其标识符。若名称与实际连接的设备不符，请重新选择它。
3. **外部混音器。** 若信号送往一个硬件混音器，请检查该通道的推子未被拉低或静音，并确认混音器的输出已连到监听或传输链。

### 音频跳帧、破音或有中断

正常情况下，音频引擎对这些杂音是稳健的。若它们出现，原因几乎总是在软件之外。

- **CPU 极度负载。** 关闭同时运行的重型应用（视频剪辑、渲染、密集备份）。
- **音频缓冲过低。** 配合专业声卡时，请检查驱动控制面板中的缓冲值。256 或 512 采样是正确的平衡；低于 128 采样可能出现 dropout。
- **磁盘缓慢或吃紧。** RLMP 从磁盘流式读取音频。一块缓慢的机械硬盘、或一块几近写满的 SSD，可能在大文件上造成中断。

### 音频电平太低或太高

- **单片段 Gain。** 在片段属性中调节 Gain（右键 → Volume 部分）。
- **主音量。** 若整体电平不对，请调整页眉中的滑块。
- **归一化与 Master Chain。** 音量归一化会把各片段的电平向一个共同参照靠拢；Master Chain 的 glue 会让声音更紧实。若某个结果不合你意，可在 设置 → 主处理链 中调节或停用这些级。

## 14.2 红色片段与文件缺失

### 一张卡片变红了（「文件缺失」），点击无反应

红色边框表示音频文件在项目所记录的路径处无法访问。

**可能原因：**

- 文件在磁盘上被移动或重命名。
- 文件曾在一个现已断开的外部磁盘或 U 盘上。
- 项目是在另一台电脑上打开的，路径不一致。

**解决办法：**

1. **重新连接磁盘。** 若文件曾在外部驱动器上，请重新接上它。
2. **把文件放回原位。** 若它被移动过，请放回原始路径。
3. **替换片段。** 把正确的文件重新拖入网格，删除红色卡片。
4. **今后使用「导出独立存档」。** 最有效的预防是在移动或转移项目之前创建一个存档（第 10 章）。

## 14.3 MIDI 问题

### 控制器未被检测到

1. **连接。** 确认控制器已连接并被操作系统识别。RLMP 实时检测设备的连接与断开；若它未出现，请拔下再重插 USB 线。
2. **驱动。** 多数 USB-MIDI 控制器是 *class-compliant* 的，无需驱动。对于带专有驱动的专业控制面，请确认驱动已安装。
3. **在 Learn 模式下验证。** 启用 MIDI Learn 并在控制器上按一个键：若卡片收到了映射，说明控制器已被检测到。

### 已映射的片段不响应控制器的按键

- **MIDI Learn 模式仍处于启用状态。** 在 MIDI Learn 中，控制器的按键会记录新映射而非触发片段。请从工具菜单停用该模式。
- **映射丢失了。** 片段的映射在 `.lmp` 文件中；请确认项目在 MIDI Learn 会话之后已保存。而全局功能的映射则与单台电脑绑定。

## 14.4 启动问题

### 应用在 macOS 上无法启动（Gatekeeper 提示）

见 2.3 节：通过 *系统设置 → 隐私与安全性* 解除限制。

### 应用在 Windows 上无法启动（SmartScreen 提示）

见 2.2 节。点击*更多信息*，再点击*仍要运行*。

### 启动时的异常行为

若软件在打开时表现异常，请关闭并重开 RLMP。若问题持续，请检查安装路径中是否含有可能干扰 FFmpeg 组件加载的特殊字符。

## 14.5 常见问题

**RLMP 能否无人值守地把一家电台自动化运行 24 小时？**
不能。RLMP 是为现场导播设计的：由操作员值守的节目。它没有按时排期，也没有播放列表的自动轮换。Automix 视图提供对纯音乐流的有限且自愿的自动化，在视图打开期间生效（第 7 章）。全天候自动化有专门的软件（Zara Radio、PlayIt Live、Rivendell）：它们回应的是不同的需求。

**「保存」与「另存为」有何区别？**
*保存项目* 静默地覆盖打开的 `.lmp` 文件。*另存为…* 始终打开对话框并创建一个新文件，不触动当前文件。

**我能在 iPad 或移动设备上用 RLMP 吗？**
不能作为主应用：RLMP 是面向 Windows、macOS 与 Linux 的桌面软件。不过平板或手机可以通过远程控制作为浏览器**遥控器**使用（第 11 章）。

**早期版本的 `.lmp` 文件与 1.11.5 兼容吗？**
兼容。打开用更早版本创建的项目时，RLMP 会自动更新其结构，包括其间新增的列，且在你执行保存之前不会修改文件。

**我如何把 RLMP 更新到新版本？**
软件在启动时检查更新并提示你。在 Windows 与 Linux AppImage 上，安装从更新窗口自动完成；在 macOS 与 Linux `.deb` 上，会在浏览器中打开下载页面。全部细节见第 12 章。

**自动备份保存在哪里？**
在应用数据目录内的 `autosaves` 文件夹中（Windows 上为 `%APPDATA%\runtime-live-machine-pro\autosaves\`；macOS 与 Linux 上为等价路径，第 10 章）。系统保留最近的十个快照。

**软件能离线运行吗？**
能，完全可以。RLMP 不需要互联网连接就能工作。网络仅用于检查更新（可选）和局域网内的远程控制（可选）。

**远程控制连不上，为什么？**
请确认远程设备与电脑处于**同一网络**、已输入**正确的 PIN**（每次启动都会变），并使用设置中显示的地址。请记住，远程控制在应用每次启动时都以关闭状态重启（第 11 章）。
