# Глава 10 — Управление проектами и сохранность данных

---

Подготовка эфира требует времени: нужно выбрать файлы, разложить их по колонкам, настроить уровни, задать fade, назначить клавиши. Эта работа — своего рода капитал, который должен пережить любую неожиданность: сбой системы, переезд на другой компьютер, возвращение к выпуску, заархивированному месяцы назад.

Сохранность данных в RLMP обеспечена на нескольких уровнях, и каждый рассчитан на конкретный риск.

---

## 10.1 Файл проекта (.lmp)

Всё состояние эфира — расположение клипов по колонкам, пользовательские имена, уровни и fade, cue-точки редактора, заметки NoteBoard, MIDI- и клавиатурные привязки, цвет колонок — сохраняется в файле с расширением **`.lmp`** (Live Machine Project).

Формат — JSON: структурированный текстовый файл, читаемый любым редактором, без привязки к конкретному производителю. Если однажды RLMP станет недоступен, данные проекта всё равно останутся читаемыми.

**Что содержит файл `.lmp`:** все перечисленные выше настройки, включая абсолютные пути к упомянутым аудиофайлам.

**Чего он не содержит:** самих аудиофайлов. `.lmp` хранит только сведения о том, где файлы лежат на диске, не копируя их содержимое. Поэтому файл проекта обычно занимает считаные килобайты — независимо от того, сколько и насколько больших файлов он затрагивает.

При открытии RLMP проверяет файл: восстанавливает возможные дублирующиеся идентификаторы, приводит значения вне диапазона в разумные пределы, а если вы открываете проект, созданный прежней версией, автоматически добавляет колонки, введённые с тех пор (Jingle, Promo), не трогая уже существующие данные.

## 10.2 Сохранение

### Быстрое сохранение

Пункт *Сохранить проект* в меню FILE сразу сохраняет открытый файл `.lmp`, без диалогового окна. Когда есть несохранённые изменения, пункт подсвечивается жёлтым — наглядное напоминание с одного взгляда. Пользуйтесь этой командой часто во время подготовки эфира.

Сохранение **атомарно**: файл сначала записывается во временную копию и лишь затем переименовывается на лету. Даже если компьютер выключится посреди записи, исходный `.lmp` недописанным не останется.

### Сохранить как

Пункт *Сохранить как…* всегда открывает диалоговое окно, даже если у проекта уже есть имя. Он пригодится, чтобы:

- Создавать последовательные версии одного эфира (`Ep47_bozza.lmp`, `Ep47_v2.lmp`, `Ep47_finale.lmp`).
- Сохранить вариант с другими настройками.
- Создать новый файл, не перезаписывая текущий.

### Защита при закрытии

RLMP непрерывно отслеживает состояние изменений. Если вы пытаетесь закрыть программу (или открыть новый проект) с несохранёнными изменениями, операция приостанавливается: появляется запрос подтверждения с тремя вариантами — сохранить, отклонить изменения или отменить. Потерять работу из-за случайного щелчка по закрытию окна невозможно.

## 10.3 Auto-Backup и автосохранение

Помимо сохранений, которые вы делаете сами, программа держит и автоматическую страховочную сеть.

**Резервная копия проекта.** Каждый раз, когда уже сохранённый проект обновляется в фоне, RLMP хранит рядом с `.lmp` копию `.bak` с последним корректным состоянием.

**Автосохранение по ротации.** Параллельно RLMP пишет снимки текущего состояния в отдельную папку приложения `autosaves` с именем на основе даты и времени. Хранятся **десять самых свежих снимков**, более старые удаляются по мере накопления новых. Эта сеть подстрахует и работу над «безымянным» проектом, который вы ни разу не сохранили на диск.

Папка `autosaves` находится в каталоге данных приложения:

- **Windows:** `%APPDATA%\runtime-live-machine-pro\autosaves\`
- **macOS:** `~/Library/Application Support/runtime-live-machine-pro/autosaves/`
- **Linux:** `~/.config/runtime-live-machine-pro/autosaves/`

**Как восстановить.** Если основной файл `.lmp` повредился или компьютер внезапно выключился, откройте папку `autosaves`, найдите снимок с датой и временем, ближайшими к моменту сбоя, и загрузите его в RLMP как обычный файл проекта. Либо переименуйте файл `.bak` рядом с проектом в `.lmp` и откройте его.

## 10.4 Export Package: полная переносимость

Файл `.lmp` содержит только пути к аудиофайлам, а не сами файлы, поэтому перенос проекта на другой компьютер требует внимания: если на машине назначения нет файлов по тем же абсолютным путям, клипы станут красными. Функция **Экспорт архива** (Export Package) в меню FILE решает проблему в корне.

### Как это работает

RLMP анализирует все пути к аудиофайлам проекта, создаёт подпапку `audio/` и **физически копирует** в неё каждый упомянутый файл. Уже присутствующие идентичные файлы заново не копируются; при совпадении имён файлы переименовываются, чтобы не перезаписать друг друга, а осиротевшие файлы, на которые в проекте больше нет ссылок, удаляются из папки.

У операции два режима:

- **Рядом с проектом** — если экспорт идёт в папку, где уже лежит `.lmp`, RLMP синхронизирует подпапку `audio/` рядом с ним.
- **Свободная папка** — если вы выбираете новую папку (USB-флешку, NAS), RLMP записывает туда `project.lmp` с путями, уже обновлёнными так, чтобы указывать на локальную подпапку `audio/`.

### Результат

Папка назначения становится самодостаточной: в ней есть всё необходимое для проведения эфира на любом компьютере с установленным RLMP, независимо от того, как там устроены папки.

> **Рекомендуемая практика.** Используйте «Экспорт архива» по завершении подготовки каждого эфира, чтобы получить «мастер» для переноса в студию или для архива. Тогда при технических проблемах в последний момент у вас всегда будет под рукой полная и переносимая копия.

### Проверка целостности при открытии

Каждый раз, когда вы открываете файл `.lmp`, RLMP выполняет автоматическую **проверку целостности**: убеждается, что каждый упомянутый аудиофайл доступен. Отсутствующие файлы отмечаются красной рамкой и меткой ФАЙЛ ОТСУТСТВУЕТ на соответствующей карточке, а остальная часть проекта — все клипы с доступными файлами — остаётся полностью рабочей.
