# Глава 9 — Запись сессии

---

Запись сессии превращает Runtime Live Machine Pro из инструмента playout в инструмент полноценного продакшна. Вместо того чтобы требовать отдельную программу записи или цепочку виртуальной маршрутизации, RLMP захватывает прямо **обработанный master mix** — то есть всё, что выходит из приложения, включая эффекты Master Chain, — в аудиофайл на диске.

---

## 9.1 Запуск записи

Управление записью находится в шапке и обозначено значком записи.

**Запуск.**
Нажмите кнопку записи. Красный индикатор и счётчик показывают, что захват идёт. Запись начинается сразу: всё, что выходит из вывода программы с этого момента, захватывается.

Иметь воспроизводимые клипы для запуска записи необязательно: захват можно начать заранее, до старта эфира, чтобы не потерять первые секунды в случае раннего старта.

**Что записывается.**
Захватываемый сигнал — это **master после лимитера**: он включает микс всех воспроизводимых клипов и обработку всей Master Chain (HPF, multiband glue, limiter). Это ровно тот сигнал, что достигает устройства аудиовывода.

**Внутренний формат.**
Во время захвата RLMP пишет сжатый поток Opus (в контейнере WebM) на 320 kbps: очень лёгкий для диска и прозрачный на слух. У непрерывной записи есть предохранительный лимит примерно в **четыре часа**; сверх этой длительности захват останавливается автоматически, чтобы не переполнить память.

**Нагрузка на систему.**
Захват идёт ниже по цепи от аудиодвижка, не нагружая Renderer. Можно записывать сессии по нескольку часов, не беспокоясь о потреблении ресурсов.

## 9.2 Остановка записи и выбор формата

Когда вы снова нажимаете кнопку, чтобы остановить запись, открывается **окно экспорта**. Это момент, когда вы выбираете, в каком формате сохранить файл: преобразование из внутреннего потока в итоговый формат берёт на себя FFmpeg.

### Доступные форматы

| Формат | Расширение | Характеристики |
|---|---|---|
| **WAV** | `.wav` | Lossless без сжатия. Максимальное качество, большие файлы. Идеален для архива и постпродакшна. |
| **FLAC** | `.flac` | Lossless со сжатием. То же качество, что у WAV, меньший размер. Идеален для архива. |
| **MP3** | `.mp3` | Lossy. Выбираемый битрейт. Идеален для распространения и подкастов. |
| **OGG** | `.ogg` | Lossy, open-source. Хорошее соотношение качества и размера. |
| **WEBM** | `.webm` | Lossy, оптимизирован для веба. Соответствует внутреннему формату захвата. |

### Опции качества

Для форматов lossless (WAV и FLAC) можно выбрать **разрядность**: 16 бит (стандарт CD), 24 бита (профессиональный broadcast-стандарт, значение по умолчанию) или 32 бита float (максимальная точность, если запись будет мастериться позже).

Для форматов lossy (MP3, OGG, WEBM) можно выбрать **битрейт** из 128, 192, 256 и 320 kbps. Для подкаста, предназначенного для распространения онлайн, 192 kbps стерео — рекомендуемый минимум; 256 kbps — текущий стандарт «прозрачного» качества.

### Выбор пути сохранения

В окне экспорта выберите папку назначения и имя файла. Если имя не указано, RLMP создаст его на основе даты и времени сессии. По завершении преобразования toast-подтверждение показывает путь сохранённого файла.

## 9.3 Практические замечания

### Синхронизация с эфиром

Запись захватывает всё время между Start и Stop, включая паузы. Если вы начали захват за 30 секунд до фактического старта эфира, итоговый файл будет включать эти 30 начальных секунд. Чтобы получить готовый к распространению результат без постобработки, запускайте запись ровно тогда, когда начинается эфир.

### Одновременные запись и резервное копирование

Система автосохранения проекта (см. Главу 10) и запись сессии работают независимо. Можно записывать эфир, пока автосохранение молча сохраняет состояние проекта: две операции не мешают друг другу.

### Рекомендуемый формат для разных контекстов

**Подкаст** — MP3 256 kbps стерео или FLAC 16 бит. Первый, если вы распространяете файл напрямую, второй — если он пойдёт через редактор.

**Исторический архив** — WAV 24 бита или FLAC 24 бита. Щедрый размер, максимальная гибкость для возможных будущих ремастеров.

**Радио / Стриминг** — сверьтесь с требованиями своей платформы. Большинство принимает MP3 128–192 kbps; некоторые требуют несжатый WAV. RLMP экспортирует в самые распространённые форматы, покрывая любой сценарий.
