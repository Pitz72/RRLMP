# v1.4.12 — Fix MEDIA-05: uncaught exception nel main dal protocollo media://

**Data:** 2026-06-10

## Bug (segnalato dalla regia durante la preparazione della live)

Caricando molti brani in PRE-SHOW è apparso il dialog **"A JavaScript error occurred in the main process — TypeError [ERR_INVALID_STATE]: Invalid state: Controller is already closed"** (stack: `ReadableStreamDefaultController.close` ← `node:internal/webstreams/adapters` ← `ReadStream.onclose`). L'app NON è crashata: era un'eccezione non gestita nel main process.

## Causa

Il protocollo `media://` serviva i file con `Readable.toWeb(nodeStream)`. L'adapter interno di Node ha una race nota: quando il **client annulla la richiesta a stream in corso** — esattamente ciò che fa il renderer durante i caricamenti di massa (`loadClip` legge i metadati e fa subito `cleanup()`, l'audio element cambia `src`) e quando un preload (v1.4.10) viene scartato — il controller web viene chiuso/cancellato, e l'evento `close` del `ReadStream` prova a **richiuderlo** → `ERR_INVALID_STATE` come uncaught exception → dialog d'errore. Con tanti file in coda la probabilità di colpire la race diventa alta. (Il churn di richieste annullate è aumentato con il preload v1.4.10, ma la race è sempre esistita.)

## Fix

Nuovo adapter manuale `toSafeWebStream(nodeStream)` al posto di `Readable.toWeb` in ENTRAMBI i rami (Range 206 e full 200):
- `close`/`error`/`enqueue` **idempotenti** (flag `done` + try/catch): la doppia chiusura diventa un no-op;
- `cancel()` (client che abbandona) **distrugge il ReadStream** (niente letture orfane);
- backpressure preservata (`pause()` quando `desiredSize ≤ 0`, `resume()` su `pull`).
Rimosso l'import `Readable` ormai inutilizzato. Nessun cambiamento di formato/headers delle risposte (206/200/416/403/404 invariati).
