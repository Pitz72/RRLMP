## Fix

### Medie (2)
- **MODAL-02** — `GeneralSettingsModal` non aveva handler ESC. Risultato: ESC su Settings aperta non chiudeva la modale ma raggiungeva il `globalShortcut` Emergency Stop → l'operatore che voleva chiudere Settings si trovava il sistema in STOP ALL. Aggiunto listener `keydown` in fase capture con `stopPropagation()` + `preventDefault()` che invoca `onClose()`.
- **MODAL-03** — `KeymappingModal` stesso problema. Il `handleKeydownCapture` interno (sulle cell input di binding) intercetta già ESC come "clear keybind" con `stopPropagation`, quindi il nuovo handler a livello modale si attiva solo quando nessuna cell ha focus — niente conflitto con la UX di binding.

### Lievi (3)
- **MODAL-04** — `enumerateDevices()` in apertura Settings senza timeout. Su Windows un device USB in stato anomalo (driver crash, hot-plug pendente) lasciava il modal in lista vuota senza segnale. Aggiunto `Promise.race` con timeout 5s + log + fallback lista vuota (il default `outputDeviceId='default'` resta sempre selezionabile via fallback).
- **MODAL-05** — `checkForUpdates()` (`utils/updateChecker.ts`) usava `fetch` nudo. Rete lenta / DNS che non risolve lasciava la Promise pendente fino al timeout TCP Chromium (~30s) → WelcomeScreen e AboutModal restavano in stato "Checking…". Aggiunto `AbortController` con timeout 5s.
- **MODAL-08** — `KeymappingModal` MIDI Learn: se durante il countdown l'utente rimuove la clip target via Canc su altra UI, `updateClip` su id orfano era un no-op silenzioso e il bind si perdeva. Aggiunta validazione esistenza `(col → clip)` prima di scrivere; se non esiste si chiude solo il pending senza scrivere.
