# v1.2.3 — Post-Release Bug Fix

**Data:** 2026-04-11

## Fix

### [BUG #01 + #02] ClipSettingsModal — colore clip non modificato se non toccato
- **Problema**: aprire le impostazioni di una clip (senza toccare il color picker) scriveva
  ugualmente il campo `customColor` con il colore corrente, perdendo il colore dinamico
  ereditato dalla colonna.
- **Soluzione**: stato `customColor` ora inizializzato a `null` (non al `clip.color` di fallback).
  `handleSave` salva `customColor: customColor ?? undefined` — solo se l'utente ha selezionato
  esplicitamente un colore.
- **Miglioramento**: palette colori clip espansa da 9 a 30 colori (stessa palette di ColumnHeader,
  griglia 6x5). Aggiunto pulsante "↺ Eredita colore dalla colonna" per resettare a `null`.
- **Display**: il dot colorato nell'header del modal ora mostra sempre il colore effettivo
  (`customColor ?? column.customColor ?? column.color`).
- **Hotfix**: corretto crash TDZ (`Cannot access 'I' before initialization`) causato da
  `effectiveDisplayColor` dichiarato prima di `customColor` (useState).

**File modificati:** `src/renderer/src/components/modals/ClipSettingsModal.tsx`

### [BUG #07] Doppio click su file .lmp apre la Welcome Screen invece del progetto
- **Problema**: l'OS registrava l'associazione file `.lmp` ma l'app ignorava il path passato
  come argomento, portando sempre alla schermata di benvenuto.
- **Soluzione**:
  - `main/index.ts`: `process.argv` viene scansionato per argomenti `.lmp` al momento di
    `app.whenReady()`. Il path viene passato a `createWindow(initialFilePath)` e inviato
    al renderer via IPC `open-file` dopo il `ready-to-show`.
  - Nuovo IPC `load-project-path`: legge il file direttamente dal path (senza dialog OS),
    con controllo `isMissing` sulle clip — stessa logica di `dialog:load-project`.
  - `preload/index.ts`: esposti `loadProjectFromPath()` e `onOpenFile()` via contextBridge.
  - `App.tsx`: `useEffect` ascolta `onOpenFile`, chiama `loadProjectFromPath`, bypassa la
    Welcome Screen se il progetto è valido. In caso di errore mostra toast.
  - `main/index.ts`: aggiunto handler `app.on('open-file')` registrato **prima** di
    `app.whenReady()` per macOS. `mainWindowRef` module-level + `pendingOpenFilePath`
    gestiscono il caso in cui il file arrivi prima che la finestra sia pronta.
- **Nota**: su Windows compare un brevissimo flash della Welcome Screen prima che il progetto
  si carichi — comportamento cosmético, non bloccante.

### [BUG #12] Voce nel recording troppo bassa (modalità hardware monitor)
- **Problema**: in modalità `mixEnabled = false` (Rodecaster e interfacce audio con monitoring
  hardware), il `micRecordingGain` era hardcoded a `3` indipendentemente dallo slider "Mic Vol".
  Il segnale USB raw risultava comunque molto più basso dell'audio processato dalla master chain.
- **Soluzione**: `micRecordingGain.gain = _volume × 8`. Lo slider "Mic Vol" nell'header ora
  controlla direttamente il livello della voce nel file di registrazione quando il Canale Mix
  è disattivato. A volume default (0.8) il gain è 6.4 (+16 dB); a volume massimo (1.0) è 8.0
  (+18 dB). Ulteriori aggiustamenti tramite slider in base alla calibrazione del mixer hardware.
- **Chiarimento modalità**:
  - **Canale Mix OFF**: per mixer/interfacce professionali (Rodecaster, ecc.) con monitoring
    hardware interno. Il mic va solo nel file di registrazione, non all'uscita dell'app.
  - **Canale Mix ON**: per microfoni USB diretti (Blue Yeti, ecc.) senza monitoring hardware.
    Il mic passa per il master chain (HPF + Comp + Limiter) e va sia all'uscita che al recording.

**File modificati:** `src/renderer/src/engine/MicManager.ts`

### [BUG #08] Ducking release — scalino netto al rilascio
- **Problema originale mal interpretato**: il *timing* del rilascio (200ms) era corretto.
  Il problema era lo *scalino netto* quando la musica risaliva: sia duck-down che duck-up
  usavano la stessa rampa di 60ms, causando un salto di volume percettibile.
- **Soluzione**:
  - Duck-down (mic attivo): rampa **60ms** — reattivo, senza lag percepibile.
  - Duck-up (mic silenzioso): rampa **400ms** — sfumatura graduale, nessuno scalino.
  - `releaseHoldMs` riportato a **200ms** (era stato portato a 600ms per errore di analisi).
  - `smoothingTimeConstant`: `0.1` → `0.15` (leggero smoothing, elimina micro-jitter).

**File modificati:**
