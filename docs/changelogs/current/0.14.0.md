# Changelog v0.14.0 (2026-04-06)

## 🔧 BUGFIX CRITICO: Smart Trim — OOM Crash su File Grandi

### Problema
Cliccare il pulsante **Auto-Trim (Wand)** nelle impostazioni clip causava un crash irreversibile del renderer (schermo bianco, app da terminare forzatamente).

### Causa Radice
La funzione `detectSilence()` eseguiva l'intera analisi audio **dentro il renderer Chromium**:
1. `response.arrayBuffer()` caricava l'intero file audio in RAM come buffer binario
2. `audioCtx.decodeAudioData()` lo decodificava in PCM Float32, raddoppiando l'occupazione di memoria

Per file WAV non compressi (tipici in broadcast), questo significava **200–600MB** allocati nel renderer in pochi millisecondi → Out-Of-Memory → crash del processo V8 → schermo bianco.

### Fix (Main-Side-Heavy Architecture)
La logica di rilevamento silenzio è stata spostata completamente nel **main process (Node.js)** seguendo l'architettura già consolidata per la generazione della waveform:

- **`AudioProcessor.ts`** — Nuovo metodo statico `detectSilence()` che usa FFmpeg con il filtro `silencedetect=noise=-40dB:d=0.1`. FFmpeg analizza il file come subprocess e ritorna solo i timestamp (`silence_start` / `silence_end`) via stderr. Zero RAM aggiuntiva nel renderer.
- **`main/index.ts`** — Nuovo IPC handler `detect-silence`.
- **`preload/index.ts`** — Esposto `detectSilence()` via contextBridge.
- **`types/index.ts`** — Aggiunto tipo `detectSilence` all'interfaccia `Window.electron`.
- **`ClipSettingsModal.tsx`** — `detectSilence()` ora chiama `window.electron.detectSilence(clip.path)` e applica i valori restituiti. Nessun `fetch`, nessun `AudioContext`, nessun buffer in-renderer.

### Fix aggiuntivo
- **`AudioProcessor.ts`** — Aggiunto handler `.on('error')` mancante su `ffStream` in `generateWaveformData()`. In assenza di questo handler, un errore sul pipe stream avrebbe emesso un evento `error` non gestito, potenzialmente crashing il main process.

### Comportamento post-fix
| Condizione | Risultato |
|---|---|
| Silenzio iniziale e/o finale rilevato | Imposta trimStart / trimEnd, mostra alert |
| Nessun silenzio rilevato | Alert informativo, nessun trim applicato |
| File non trovato | Messaggio di errore |
| Intero file silenzioso | Messaggio di errore specifico |
