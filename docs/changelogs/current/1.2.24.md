# v1.2.24 — Fix NEW-ME-03 sanitize numerici .lmp

**Data:** 2026-05-16

## Fix media

### NEW-ME-03 — `validateLmpProjectData` non controllava i campi numerici

- **Problema**: `validateLmpProjectData` (introdotta in v1.2.10 con ME-02) controllava tipi base (id/name/path/type stringhe) ma non sanitizzava i campi numerici delle clip. Un `.lmp` con `volume: NaN`, `trimStart: 1e10` o `fadeIn: Infinity` veniva caricato as-is. Conseguenze:
  - `volume: NaN` → `gainNode.gain.value = NaN` → bus muto fino a riavvio o intervento manuale.
  - `trimStart: 1e10` → seek oltre la fine della clip → clip non parte mai o sallta direttamente a `ended`.
  - `fadeIn: Infinity` → setTimeout fade impossibile → comportamento UB.
- **Fix** in `src/renderer/src/store/useProjectStore.ts`:
  - Helper `finiteOrDefault(val, def, min?, max?)` ritorna `def` se `val` non è un numero finito, altrimenti clamp tra `min` e `max`.
  - Per ogni clip, sanitize in-place:
    - `volume` → default 1.0, clamp [0, 1.5]
    - `pan` → default 0, clamp [-1, 1]
    - `duration`, `trimStart`, `trimEnd`, `introMarker`, `outroMarker` → default 0, min 0
    - `fadeIn`, `fadeOut` → default 0, clamp [0, 60000] ms
  - Sanitize silenzioso (no throw) per mantenere robusto il caricamento di `.lmp` legacy o con campi mancanti.
