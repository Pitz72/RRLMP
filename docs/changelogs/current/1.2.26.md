# v1.2.26 — Fix NEW-ME-05 permission handler audio-only

**Data:** 2026-05-16

## Fix media

### NEW-ME-05 — `setPermissionRequestHandler` approvava anche le richieste video

- **Problema**: l'handler di permessi in `src/main/index.ts` (v0.17.0) approvava qualsiasi richiesta `permission === 'media'` senza distinguere audio da video. RRLMP non usa la webcam in nessun flusso utente, ma una libreria di terze parti caricata via supply-chain attack avrebbe potuto fare `getUserMedia({video: true})` senza prompt né traccia visibile. Scenario di esfiltrazione realistico per uno studio broadcast con webcam fisica connessa.
- **Fix** in `src/main/index.ts`: usato il quarto parametro `details` di `setPermissionRequestHandler` che in Electron 28 espone `mediaTypes: string[]`. Se la richiesta include `'video'`, viene negata. Audio puro passa. Fallback permissivo se `mediaTypes` è assente (Electron più vecchio): comunque il constraint nel renderer è già `{audio: ..., video: false}`, quindi non si può ottenere video lato Web API.
