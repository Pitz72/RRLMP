# Changelog v0.14.7 (2026-04-07)

## Feature Release: Toast Notification System

Sostituisce tutti i `alert()` e `confirm()` nativi del browser con un sistema di notifiche non-bloccante e un dialog di conferma inline. Elimina il principale problema di professionalità broadcast: l'interfaccia che si congela durante la messa in onda.

---

## 🔔 Toast Notification System

### Problema risolto

Tutti i messaggi di errore, avviso e conferma usavano `alert()` / `confirm()` nativi del browser, che:
- **Bloccano completamente l'interfaccia** — inaccettabile durante una trasmissione live
- Non hanno stile coerente con l'app
- Non possono essere accodati o ignorati dall'operatore
- Non sono disponibili in contesto Electron senza attivazione manuale

### Architettura

**`useToastStore`** (Zustand) — store globale toast:
- `addToast(message, type, duration?)` — aggiunge un toast con auto-dismiss
- `removeToast(id)` — rimozione manuale via pulsante X
- `toast()` — helper callable da qualsiasi file senza hook React
- Tipi: `success` (4s), `error` (6s), `warning` (4s), `info` (4s)
- Stack max 5 toast visibili contemporaneamente

**`useConfirmStore`** (Zustand) — dialog di conferma promise-based:
- `confirm(message, confirmLabel?, cancelLabel?)` → `Promise<boolean>`
- Non-bloccante: usa `await` nei gestori async invece di bloccare il thread
- Helper `confirm()` callable da qualsiasi file

**`ToastContainer`** — UI toast:
- Posizione fixed bottom-right, z-index 200
- Icona per tipo (✓ success, ✕ error, ⚠ warning, ℹ info)
- Barra di progresso CSS animata che indica il tempo rimanente
- Pulsante X per chiusura manuale
- Colori: emerald (success), red (error), amber (warning), cyan (info)

**`ConfirmDialog`** — UI conferma:
- Modal overlay con z-index 300 (sopra i toast)
- Icona ⚠ amber, messaggio, pulsanti Conferma/Annulla personalizzabili
- `autoFocus` sul pulsante Conferma per workflow tastiera rapido
- Stile coerente con il resto dell'app (zinc/dark)
