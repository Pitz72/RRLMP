## 1 — Volume Master MIDI: fader CC continuo con slider reattivo

**Problema precedente**: il binding MIDI `masterVolume` già esisteva ma aggiornava solo `AudioContextManager` internamente. Lo slider UI non si muoveva quando si alzava/abbassava il fader fisico MIDI.

**Soluzione**: `masterVolume` è ora uno stato persistito in `useSettingsStore` (localStorage), condiviso tra UI e handler MIDI.

### Flusso aggiornato

```
[Fader MIDI CC 0-127]
        ↓
App.tsx handleMidiMessage → globalAction === 'masterVolume'
        ↓
AudioContextManager.setMasterVolume(vol)   ← audio reale
useSettingsStore.setMasterVolume(vol)      ← store reattivo
        ↓
GlobalControls slider value={masterVolume} ← UI segue il fader
```

### Persistenza

Il volume viene salvato in localStorage. Al prossimo avvio, `GlobalControls` applica il valore persistito ad `AudioContextManager` nel mount `useEffect`, così il volume si ricorda tra le sessioni.

### File modificati

| File | Modifica |
|------|----------|
| `src/renderer/src/store/useSettingsStore.ts` | Aggiunto `masterVolume: number` (default 1.0) + `setMasterVolume(v)` |
| `src/renderer/src/components/ui/GlobalControls.tsx` | Slider usa `masterVolume` da store invece di `useState`; sync iniziale applica valore persistito |
| `src/renderer/src/App.tsx` | Handler MIDI chiama anche `setMasterVolume()` dopo `AudioContextManager.setMasterVolume()` |

## 2 — Badge "Auto-saved" nell'header

Dopo ogni auto-backup riuscito (ogni 5 minuti), appare per **3 secondi** un piccolo badge verde "✓ Auto-saved" nella barra dei controlli, a destra dei pulsanti toolbar.

- Transizione `opacity` fluida (fade-in/fade-out via Tailwind `transition-opacity duration-500`)
- Non è un toast, non interrompe l'operatore — è un feedback visivo minimo e contestuale
- Se il backup fallisce, il badge non appare (solo log debug come prima)
- Implementato con `showAutoSaved: boolean` locale in `GlobalControls`, reset automatico con `setTimeout(3000)`

## 3 — Drop da OS file manager a posizione precisa

*(già rilasciato tra v0.15.0 e v0.16.0 — incluso in questo log per completezza)*

File audio trascinati dall'explorer di sistema si inseriscono ora nel punto esatto del rilascio invece di andare sempre in fondo alla colonna.

- Nuovo `addClipAtIndex(columnId, file, index)` in `useProjectStore`
- `handleNativeDrop` in `MainGrid` calcola l'indice dal `clientY` confrontando il midpoint Y di ogni `[data-clip-id]`
- Drop multiplo incrementa l'indice progressivamente per preservare l'ordine dei file
