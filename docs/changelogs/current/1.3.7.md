## Fix

### Grave (1)
- **BUILD-02** — Nessun `app.requestSingleInstanceLock()`: un doppio-click rapido sull'icona, un drop di `.lmp` su app già aperta o un pin in taskbar potevano lanciare DUE istanze RRLMP simultaneamente → output audio duplicato sullo stesso device fisico (disastro in diretta). Aggiunto lock prima di `app.whenReady()`: la seconda istanza esce immediatamente; nella prima istanza l'handler `'second-instance'` porta la finestra in primo piano (con `restore()` se minimizzata) e inoltra l'eventuale `.lmp` passato come argv via IPC `open-file` (riusa la pipeline `onOpenFile` già esistente nel renderer).

### Media (2)
- **BUILD-01** — `app.setAppUserModelId('com.electron')` era hardcoded al placeholder default di Electron, NON allineato a `package.json build.appId = 'com.antigravity.rrlmp'`. Su Windows questo crea mismatch con: jump list (icona generica), file association `.lmp` (registry sotto AppUserModelId sbagliato), toast notifications (raggruppate sotto "Electron Framework"). Corretto a `'com.antigravity.rrlmp'`.
- **BUILD-05** — `checkForUpdates` veniva chiamata ad ogni mount di `WelcomeScreen` e ad ogni apertura di `AboutModal`: utente che apre/chiude RRLMP 10× al giorno per test = 10+ hit al server `versions.json`. Aggiunto cache `localStorage` con TTL 24h: la chiamata `checkForUpdates(version)` ritorna il risultato cached se l'ultimo check (per la stessa versione) è andato a buon fine entro 24h. Cache invalidata automaticamente quando l'utente aggiorna l'app (currentVersion cambia). Aggiunto secondo argomento `force: boolean = false` per consentire al futuro bottone "Controlla ora" di bypassare. I fallimenti non vengono cached.
