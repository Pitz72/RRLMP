# v1.2.21 — Fix NEW-GR-06 CSP production hardening

**Data:** 2026-05-16

## Fix grave

### NEW-GR-06 — `'unsafe-eval'` nella CSP anche in produzione

- **Problema**: l'header `Content-Security-Policy` iniettato via `onHeadersReceived` includeva `script-src 'self' 'unsafe-inline' 'unsafe-eval'` in tutti gli ambienti. `'unsafe-eval'` è necessario solo per il fast refresh di Vite in development; il bundle di produzione non usa `eval()`. Mantenerlo in prod amplifica la superficie di attacco XSS senza alcun beneficio funzionale. Combinato con `'unsafe-inline'`, di fatto annullava la protezione CSP. Scenario di rischio: apertura di un `.lmp` di terzi contenente nomi clip/note con payload XSS che riesce a riflettersi in qualche componente non escapato → eval di payload arbitrario → accesso al contextBridge (`window.electron.*`).
- **Fix** in `src/main/index.ts`:
  - Branch su `process.env.NODE_ENV === 'development'`.
  - In dev: `script-src 'self' 'unsafe-inline' 'unsafe-eval'` (Vite HMR/fast-refresh).
  - In prod: `script-src 'self' 'unsafe-inline'` (no eval).
  - `'unsafe-inline'` resta in entrambi per gli style inline generati da React e librerie.
