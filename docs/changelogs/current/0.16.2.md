## 1 — Colore Clip: Tonalità Schiarita verso il Bianco

### Problema risolto

In v0.16.1, il nome delle clip idle veniva tinto con `clip.color + 'aa'` (aggiungendo opacity 67% in hex). Su sfondo scuro (`zinc-900`), questa semitrasparenza produceva una tinta opaca e piuttosto fioca, difficile da leggere e poco leggibile in condizioni di scarsa illuminazione tipiche delle regie radio.

### Implementazione

Aggiunta funzione `lightenHex(hex, amount)` in `ClipCard.tsx`:

```typescript
const lightenHex = (hex: string, amount = 0.65): string => {
    // Mescola il colore con il bianco nella percentuale indicata
    // amount = 0.65 → 65% bianco, 35% colore originale
    // Es: #ff0000 (rosso) → #ffa3a3 (rosa pallido)
    //     #8B5CF6 (violet) → #cdb8f9 (lavanda chiara)
    //     #EF4444 (red)    → #f7a0a0 (salmone chiaro)
    ...
};
```

Sostituzione in `ClipCard.tsx` riga ~185:
```
// PRIMA: clip.color + 'aa'  → colore con 67% opacity (opaco/fioco)
// DOPO:  lightenHex(clip.color) → blend 65% con bianco (luminoso, pastello)
```

### Comportamento visivo

| Stato clip | Colore nome |
|------------|-------------|
| Idle (non in play) | `lightenHex(clip.color, 0.65)` — versione chiara pastello |
| In play | `clip.customColor \|\| '#4ade80'` — verde vivace (invariato) |
| Mancante | `#ef4444` — rosso (invariato) |

Il risultato è un testo più leggibile e visivamente "moderno", che mantiene la riconoscibilità del colore colonna senza essere aggressivo.

**File modificati**: `src/renderer/src/components/layout/ClipCard.tsx`

## 2 — Drop Indicator: Linea di Inserimento durante Drag & Drop da OS

### Problema risolto

Quando si trascinava un file audio dall'OS (Esplora File / Desktop) verso una colonna, il punto di inserimento era calcolato correttamente ma non veniva mostrato all'utente. L'operatore non aveva feedback visivo su dove esattamente la clip sarebbe atterrata, specialmente in colonne affollate.

### Implementazione

**Stato React** aggiunto in `MainGrid.tsx`:
```typescript
const [dropIndicator, setDropIndicator] = useState<{ colId: string; index: number } | null>(null);
```

**`handleNativeDragOver`** ora calcola l'indice in real-time e aggiorna lo stato:
```typescript
const handleNativeDragOver = (e: React.DragEvent, colId: string) => {
    e.preventDefault();
    const clipEls = e.currentTarget.querySelectorAll('[data-clip-id]');
    let insertIndex = clipEls.length; // default: in fondo
    for (let i = 0; i < clipEls.length; i++) {
        const rect = clipEls[i].getBoundingClientRect();
        if (e.clientY < rect.top + rect.height / 2) {
            insertIndex = i;
            break;
        }
    }
    setDropIndicator({ colId, index: insertIndex });
};
```

**`handleNativeDragLeave`** aggiunto — cancella il marker solo quando il puntatore esce dalla colonna (non quando transita tra figli interni):
```typescript
const handleNativeDragLeave = (e: React.DragEvent) => {
    if (!e.currentTarget.contains(e.relatedTarget as Node)) {
        setDropIndicator(null);
    }
};
```

**Rendering della linea indicatore** — inserita tra le `SortableClip` tramite `React.Fragment`:
```tsx
{col.clips.map((clip, idx) => (
    <React.Fragment key={clip.id}>
        {dropIndicator?.colId === col.id && dropIndicator.index === idx && (
            <div className="h-0.5 rounded mx-0.5 shadow-[0_0_8px_rgba(96,165,250,0.9)]"
                 style={{ backgroundColor: '#60a5fa' }} />
        )}
        <SortableClip clip={clip} ... />
    </React.Fragment>
))}
{/* Indicatore in coda */}
{dropIndicator?.colId === col.id && dropIndicator.index === col.clips.length && (
    <div className="h-0.5 rounded mx-0.5 shadow-[0_0_8px_rgba(96,165,250,0.9)]"
         style={{ backgroundColor: '#60a5fa' }} />
)}
```

**Pulizia automatica**: l'indicatore viene rimosso sia al `drop` che al `dragLeave`.

### Aspetto visivo

- Linea sottile (2px) **blu accesa** (`#60a5fa` = blue-400 Tailwind)
- Glow luminoso (`box-shadow` 8px, 90% opacity)
- Appare istantaneamente tra i clip al passaggio del mouse
- Si sposta fluentemente seguendo il puntatore
- Sparisce appena il file viene rilasciato o il cursore esce dalla colonna

**File modificati**: `src/renderer/src/components/layout/MainGrid.tsx`

## 3 — Master Chain Audio (Broadcast-Grade Sound Processing)

### Overview

Implementata una pipeline di elaborazione audio professionale sul master bus, pensata per l'utilizzo in regia radiofonica broadcast. La chain è completamente controllabile dall'utente e persiste tra le sessioni.

### Topologia Audio (aggiornata)

```
Bus (Music / Voice / SFX / Assets)
    → masterGain
        → HPF (HighPassFilter)
            → Compressor (DynamicsCompressor broadcast)
                → Limiter (brickwall, DynamicsCompressor)
                    → AudioContext.destination
                    → ChannelSplitter → AnalyserL, AnalyserR (VU meter)
```

**PRIMA (v0.16.1):**
```
Buses → masterGain → destination
                   → splitter → analyserL, analyserR
```

### Stadi della Chain

#### HPF — High-Pass Filter
- **Tipo**: `BiquadFilterNode`, type `highpass`
- **Frequenza di taglio default**: 80 Hz
- **Q**: 0.7 (pendenza naturale, non risonante)
- **Funzione**: elimina rumble da microfono, fruscio a bassa frequenza, DC offset e interferenze
- **Bypass**: `type = 'allpass'` (pass-through neutro senza disconnettere il nodo)
- **Range UI**: 20 Hz – 200 Hz

#### Compressore Broadcast
- **Tipo**: `DynamicsCompressorNode`
- **Parametri default**: threshold -18 dBFS, knee 6 dB, ratio 4:1
- **Attack**: 5 ms (veloce, cattura transienti voce)
- **Release**: 200 ms (naturale per musica broadcast)
- **Funzione**: levela il mix, riduce la dinamica eccessiva mantenendo la presenza vocale e musicale
- **Bypass**: `threshold = 0, ratio = 1` (nessuna compressione applicata)
- **Range UI**: threshold -40..-6 dBFS, ratio 1..20:1

#### Limiter Brickwall
- **Tipo**: `DynamicsCompressorNode` configurato come limiter
- **Parametri default**: threshold -1 dBFS, knee 0 dB, ratio 20:1
- **Attack**: 1 ms (praticamente istantaneo)
- **Release**: 100 ms
- **Funzione**: sicurezza assoluta del segnale in uscita — protegge la catena trasmittente/registratore da clipping digitale
- **Note**: sempre attivo quando la chain è abilitata (non può essere bypassato singolarmente per sicurezza broadcast)
- **Range UI**: threshold -6..-0.1 dBFS

### Bypass dell'intera chain

Quando `masterChainEnabled = false`:
- HPF → `type = 'allpass'`
- Compressor → `threshold = 0, ratio = 1`
- Limiter → `threshold = 0, ratio = 1`

Il grafo audio resta fisicamente connesso — il bypass agisce sui parametri, non sulla topologia. Questo elimina click/artifact da riconnessione e mantiene la latenza costante.

### Persistenza Impostazioni

Nuovo campo `masterChain: MasterChainSettings` aggiunto a `useSettingsStore` (persisted via `rrlmp-settings` in localStorage):

```typescript
interface MasterChainSettings {
    enabled: boolean;           // Chain attiva/bypassa tutto
    hpfEnabled: boolean;        // HPF on/off
    hpfFrequency: number;       // Hz — default 80
    compressorEnabled: boolean; // Compressor on/off
    compressorThreshold: number;// dBFS — default -18
    compressorRatio: number;    // default 4
    limiterThreshold: number;   // dBFS — default -1
}
```

Valori default (`DEFAULT_MASTER_CHAIN` esportato da `AudioContextManager.ts`):
```typescript
{ enabled: true, hpfEnabled: true, hpfFrequency: 80,
  compressorEnabled: true, compressorThreshold: -18, compressorRatio: 4,
  limiterThreshold: -1 }
```

### Sincronizzazione UI → Audio

In `App.tsx`, aggiunto `useEffect` che chiama `AudioContextManager.getInstance().applyMasterChainSettings(masterChain)` ogni volta che le impostazioni cambiano:

```typescript
const masterChain = useSettingsStore((s) => s.masterChain);
useEffect(() => {
    AudioContextManager.getInstance().applyMasterChainSettings(masterChain);
}, [masterChain]);
```

I parametri vengono applicati con `setTargetAtTime(value, now, 0.05)` — transizione liscia di 50 ms, nessun glitch.

### UI in GeneralSettingsModal

Nuova sezione **"Master Chain"** in fondo al modal impostazioni, con:

- **Toggle globale** On/Bypass — disabilita/abilita l'intera pipeline
- **HPF**: toggle on/off + slider frequenza (20–200 Hz, step 5)
- **Compressore Broadcast**: toggle on/off + slider soglia (-40..-6 dBFS) + slider ratio (1..20:1)
- **Limiter Brickwall**: solo slider soglia (-6..-0.1 dBFS, step 0.1)
- **Pulsante "↺ Ripristina default"** — riporta tutti i parametri ai valori standard broadcast

Colore accent: **sky-400** (blu) per distinguere visivamente dalla sezione Mixing Intelligence (emerald).

### Metodi pubblici aggiunti ad `AudioContextManager`

```typescript
applyMasterChainSettings(s: MasterChainSettings): void
getCompressorReduction(): number  // gain reduction in dB (debug/metering)
getLimiterReduction(): number     // gain reduction in dB (debug/metering)
```
