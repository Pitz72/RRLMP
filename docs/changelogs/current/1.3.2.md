---

## Fix

### Medie (2)
- **MIDI-01** — `MidiManager.init()` `onstatechange`: alla disconnessione di una porta input viene ora azzerato `e.port.onmidimessage = null`. Senza questo cleanup, alla riconnessione della stessa porta il browser può mantenere il binding precedente *e* aggiungerne uno nuovo, causando trigger doppio (ogni nota MIDI lanciava la clip due volte).
- **MIDI-02** — `App.tsx handleMidiMessage`: aggiunto guard `note` e `velocity` clampati a `[0, 127]` con `Math.floor` prima di qualsiasi uso a valle (`velocity/127` per masterVolume e `velocityGain` per `playClip`). Difesa contro device fuori spec o pacchetti corrotti che potrebbero inviare valori > 127 — il clamp esistente in `useAudioStore.ts:273` è sul prodotto finale `volume*velocityGain`, non sul moltiplicatore in ingresso.

### Lieve (1)
- **MIDI-03** — sostituzioni `console.warn`/`console.error` con `debugLog()` / `useDebugStore.log()` strutturato (pattern LI-03):
  - `MidiManager.ts:35` "MIDI API non supportata" → `debugLog(..., 'error')`
  - `MidiManager.ts:91` "MIDI Init Failed" → `debugLog(..., 'error')`
  - `App.tsx:270` "Seleziona una clip per assegnare il MIDI" → `useDebugStore.log(..., 'event')`
