# Changelog v0.14.2 (2026-04-06)

## 🛡️ Feature Release: LMP Integrity Check

Questa release implementa il punto **§4.1** della VISION.md ("LMP Integrity Check", priorità 🔴 CRITICO). All'apertura di un progetto `.lmp`, il sistema verifica automaticamente l'esistenza su disco di tutti i file audio referenziati. Le clip con file mancanti vengono marcate visivamente e bloccate in playback senza interrompere il caricamento del progetto.

---

## 🔍 Funzionamento

### Flusso di caricamento con Integrity Check

1. L'utente apre un file `.lmp` tramite il pulsante Carica (o da Welcome Screen)
2. `loadProject()` carica le colonne nello store, resettando `isMissing: false` su tutte le clip
3. Subito dopo, `runIntegrityCheck()` viene chiamato in modo asincrono
4. Il renderer invia tutti i path via IPC al main process (`check-files-exist`)
5. Il main verifica `fs.existsSync()` per ogni path e ritorna l'array dei mancanti
6. Lo store aggiorna `isMissing: true` sulle clip corrispondenti
7. Le ClipCard si re-renderizzano: clip mancanti mostrano lo stato di errore visivo

### Caratteristiche

- **Non-blocking**: il caricamento del progetto non viene bloccato dai file mancanti. Le clip presenti funzionano normalmente
- **Runtime only**: `isMissing` è un flag di stato volatile, non viene serializzato nel `.lmp`
- **Sicuro su reset**: `loadProject()` resetta `isMissing: false` su tutte le clip prima del check

## 🎨 Stato Visivo Clip Mancante

Quando `clip.isMissing === true`, la ClipCard mostra:
- **Sfondo rosso scuro** (`bg-red-950/60`) con bordo rosso (`border-red-800`)
- **Cursore `not-allowed`** invece di `pointer`
- **Overlay centrale** con icona ⚠️ e testo "FILE MANCANTE"
- Il contenuto normale della card (nome, timer, tag) rimane visibile sotto l'overlay

### Blocco Playback
- Click sulla ClipCard: ignorato se `clip.isMissing` (early return nel `handleClick`)
- `useAudioStore.playClip()`: early return con `debugLog('warn')` se `freshClip.isMissing`
- Doppia protezione: UI + engine, garantisce che nessun path code raggiunga il player

## 🏗️ Architettura IPC

### Main Process (`check-files-exist`)
```typescript
ipcMain.handle('check-files-exist', async (_event, paths: string[]) => {
    const missing = (paths as string[]).filter(p => !fs.existsSync(p));
    return { missing };
});
```

### Preload Bridge
```typescript
checkFilesExist: (paths: string[]) => ipcRenderer.invoke('check-files-exist', paths),
```

### Store Action
```typescript
runIntegrityCheck: async () => {
    const state = useProjectStore.getState();
    const allClips = state.columns.flatMap(col => col.clips);
    const paths = allClips.map(c => c.path).filter(Boolean);
    if (paths.length === 0) return 0;

    const { missing } = await window.electron.checkFilesExist(paths);
    const missingSet = new Set(missing);

    set((s) => ({
        columns: s.columns.map(col => ({
            ...col,
            clips: col.clips.map(c => ({ ...c, isMissing: missingSet.has(c.path) }))
        }))
    }));

    return missing.length;
},
```

## ⚠️ Limitazioni Note

- Il check viene eseguito **solo al caricamento** del progetto, non in background durante l'esecuzione
- Non viene fornito un pannello di re-link per sostituire i path dei file mancanti (feature §4.1b, backloggata)
- I file rimossi o spostati **dopo** il caricamento non vengono rilevati (no filesystem watcher)
- Nessun feedback visivo aggregato (es. toast "N file mancanti") — solo `console.warn`. Pianificato come miglioramento futuro
