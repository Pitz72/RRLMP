# Changelog v0.11.2 (2026-04-06)

## 🚑 HOTFIX DEFINITIVO: FFprobe e ASAR Unpacking
Analisi forense e correzione totale dei path per la comunicazione Child Process nell'ambiente pacchettizzato.

### 🐛 Il Problema: `TypeError ASAR/Undefined`
Nonostante l'hotfix precedente avesse ripreso la compatibilità CJS nativa di Node, l'eseguibile ha provocato in Main Process l'errore d'avvio: `TypeError: Cannot read properties of undefined (reading 'path')`.
1. **ESM Interop CJS**: L'importazione ES6 `import ffprobeStatic from 'ffprobe-static'` traslata dal bundler Vite si aspettava l'oggetto sotto `default`, fallendo miseramente nell'output asar e producendo `undefined`.
2. **ASAR File System Lock**: Le estensioni statiche `.exe` racchiuse nel file `app.asar` generato da Electron-Builder non venivano estratte, rendendo vano lo `spawn()` del Child Process FFmpeg, dato che un eseguibile locale Windows non può runnare all'interno di un ghost-zip tree.

### 🛠️ La Soluzione Forense
- **Require Strict & Defensive Coding**: Inettata la funzione `require` nativa forzando il caricamento dell'Object Export (`require('ffprobe-static')`) con fallback dinamico alla proprietà effettiva per prevenire TypeErrors.
- **ASAR Unpack**: Scritte regole in `package.json` (`"asarUnpack"`) obbligando *NSIS* ad estrarre in clair-text i path `node_modules/ffmpeg-static/**/*.exe` su disco.
- **Virtual Path Hack**: Inserita la patch industriale `replace('app.asar', 'app.asar.unpacked')` che riconosce dinamicamente la nuova sandbox unpacked in produzione e previene `ENOENT`.

Ora le librerie statiche operano su vero File-System Windows!
