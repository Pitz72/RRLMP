## 🔴 UP NEXT Badge Dinamico (§4.3)

### Comportamento

Il badge **▶ UP NEXT** appare sulla clip che verrà riprodotta **automaticamente** come prossima, in base allo stato corrente di playback — non sul valore statico di `nextAction`.

**Condizioni di attivazione:**
1. Una clip nella stessa colonna è attualmente in riproduzione
2. La clip in play ha `nextAction === 'play_next'`
3. Questa clip è immediatamente successiva nella lista

**Differenza dal badge NEXT esistente:**
| Badge | Quando appare | Significato |
|-------|--------------|-------------|
| `NEXT` (emerald) | Sempre, se `nextAction = play_next` | Proprietà statica — "questa clip ha l'autoplay" |
| `▶ UP NEXT` (violet, pulsante) | Dinamicamente, durante la riproduzione | Stato live — "questa è la prossima clip IN CODA ORA" |

I due badge sono mutualmente esclusivi: quando `isNextUp` è true, il badge NEXT statico viene nascosto e sostituito da UP NEXT.

### Visual Design

- Colore: **violet** (`bg-violet-500`)
- Glow effect: `shadow-[0_0_6px_rgba(139,92,246,0.7)]`
- Animazione: `animate-pulse` per indicare stato live
- Testo: `▶ UP NEXT`

### Implementazione

Il calcolo di `isNextUp` è completamente reattivo: è un `useMemo` che dipende da `useAudioStore.activeClips` e `useProjectStore.columns`. Si aggiorna automaticamente a ogni cambio di playback.

```typescript
// In ClipCard
const isNextUp = React.useMemo(() => {
    const col = columns.find(c => c.clips.some(cl => cl.id === clip.id));
    if (!col) return false;
    const clipIdx = col.clips.findIndex(c => c.id === clip.id);
    if (clipIdx <= 0) return false;
    const prevClip = col.clips[clipIdx - 1];
    return prevClip.nextAction === 'play_next' && !!activeClips[prevClip.id];
}, [columns, activeClips, clip.id]);
```

## 📋 Note/Script per Clip (§4.5)

### Campo `notes`

Nuovo campo `notes?: string` su `AudioClip` — testo libero per script, cue sheet, note di regia o qualsiasi annotazione operativa. È **persistito nel file `.lmp`** (serializzato nel JSON del progetto).

### Tab "Notes / Script" nel Modal

Il `ClipSettingsModal` ora ha tre tab:

1. **General Settings** (esistente) — nome, volume, comportamento
2. **Trim & Markers** (esistente) — waveform editor, fade, marker
3. **Notes / Script** (nuovo) — textarea monospace + contatori

**Caratteristiche della tab Notes:**
- Textarea monospace (`font-mono`) con 16 righe visibili e resize disabilitato (scroll interno)
- `spellCheck={false}` — testo tecnico, nessun controllo ortografico
- Contatore caratteri e righe non-vuote in tempo reale
- Pulsante "Cancella" contestuale (appare solo se ci sono note)
- Indicatore `●` violet sul tab quando la clip ha note
- Il tab mostra il punto `●` anche prima di aprirlo, come reminder visivo

### Indicatore su ClipCard

Quando `clip.notes` è non-vuoto, la ClipCard mostra il badge `📋` (grigio, discreto) nei tag visivi. Il titolo del badge (tooltip) mostra il testo completo al hover.

## 🎨 UX Notes

### UP NEXT — coerenza con il sistema esistente

Il badge UP NEXT non interferisce con la logica di sequencing. È puramente informativo: mostra all'operatore broadcast qual è la clip in coda senza modificarne il comportamento.

Il badge appare e scompare dinamicamente:
- Appare: quando la clip precedente inizia la riproduzione con `play_next`
- Scompare: quando la clip precedente finisce (e questa inizia) o viene stoppata

### Note — non blocking

Le note non influenzano nessuna logica audio. Sono un campo editoriale puro, pensato per:
- Script radio da leggere durante la clip
- Note tecniche ("alzare -3dB live", "fade manuale")
- Cue operativi ("aspetta stacco prima di entrare")
- Qualsiasi testo libero utile in diretta
