# v1.15.14 — Progetti esportati portabili: le clip suonano anche su un'altra macchina

**Data:** 2026-07-22

## Correzioni

- **L'archivio esportato non suonava su un altro PC (o in un'altra cartella)**: il `.lmp` salva i path assoluti della macchina di origine, quindi dopo uno zip→invio→dezip le clip apparivano al loro posto ma non partivano (i file puntavano a percorsi inesistenti). Ora, all'apertura del progetto, ogni file non trovato viene cercato automaticamente nella cartella `audio/` accanto al `.lmp` (il layout garantito dall'export): se c'è, la clip viene ripuntata lì e torna riproducibile senza alcun intervento. Il progetto risulta "modificato" — al salvataggio successivo i percorsi ripuntati vengono consolidati per la macchina corrente.
- **Il controllo di integrità dei file ora gira su TUTTE le vie di apertura**: prima partiva solo dal pulsante Carica; doppio click sul file `.lmp` e schermata di benvenuto non lo eseguivano — un progetto con file mancanti si apriva senza alcuna segnalazione (clip normali che non suonavano al click). Ora tutte e tre le vie controllano e riparano.
- **Path relativi nel `.lmp` ora risolti correttamente**: il `project.lmp` scritto dall'export "libero" (senza progetto salvato) contiene percorsi relativi `audio/...` che l'app non sapeva risolvere. Ora vengono risolti contro la cartella del `.lmp` all'apertura.

## Note tecniche

- Nuovo `src/renderer/src/utils/pathPortability.ts` (puro, testato): `isAbsolutePath`, `dirnameOf`, `basenameOf`, `resolveClipPath` (relativo → assoluto contro la dir del `.lmp`), `audioFallbackCandidate` (candidato di riparazione `<dir .lmp>/audio/<nomefile>`, cross-platform Windows↔macOS/Linux, UNC inclusi).
- `useProjectStore.loadProject`: risoluzione dei path relativi al load (a runtime motore/FFmpeg/`media://` richiedono assoluti — la risoluzione avviene una volta sola all'apertura).
- `useProjectStore.runIntegrityCheck`: per i file assenti tenta la riparazione via `audio/` accanto al `.lmp` (secondo giro di `check-files-exist` sui soli candidati); ripuntamento ⇒ `isDirty: true`; ritorna il numero di file ancora mancanti dopo la riparazione.
- `App.tsx`: `runIntegrityCheck()` aggiunto ai flussi open-file (doppio click) e WelcomeScreen.
- 11 nuovi test Vitest (`pathPortability.test.ts`) — suite 172/172, typecheck 0 su main/preload/renderer.
