# v1.2.15 — Intelligent Auto-Silence Detection

**Data:** 2026-05-16

## Miglioramento

### Auto-Silence Detection — soglia dinamica basata su volumedetect

- **Problema**: `AudioProcessor.detectSilence()` usava una soglia fissa di -40 dB hardcoded. Per file con rumore di fondo elevato (registrazioni field, file non masterizzati) la soglia era troppo bassa e non rilevava il silenzio. Per file a basso volume globale, era invece troppo alta.

- **Fix**:
  - Aggiunto metodo privato `_estimateMeanLevel(filePath)`: esegue FFmpeg con filtro `volumedetect` limitato ai primi 60 secondi del file (timeout 10s). Ritorna `mean_volume` in dBFS.
  - `detectSilence()` ora calcola la soglia dinamicamente: `max(-55, min(-20, meanLevel - 25))` dBFS.
    - File mastered a -10 dBFS → soglia ≈ -35 dBFS (standard per musica commerciale)
    - Registrazione vocale a -25 dBFS → soglia ≈ -50 dBFS (cattura pause naturali del parlato)
    - Se `volumedetect` fallisce → fallback a -40 dBFS (comportamento precedente)
  - `detectSilence(filePath, overrideThresholdDb?)`: nuovo parametro opzionale per forzare una soglia manuale (utile per la chiamata dal `ClipSettingsModal` Auto-Trim con slider futuro).
  - Timeout IPC aumentato da 30s a 45s per coprire le due passate FFmpeg.
  - Risultato ora include `thresholdUsed: number` nei dati ritornati (per debugging/UI futura).

- **Propagazione IPC/preload/types**:
  - `src/main/index.ts`: handler accetta `thresholdDb?: number`
  - `src/preload/index.ts`: espone parametro opzionale
  - `src/renderer/src/types/index.ts`: aggiornato tipo `detectSilence`

- **Backward compatibility**: tutti i caller esistenti (MainGrid, GlobalControls, ClipSettingsModal) non richiedono modifiche — il parametro è opzionale.
