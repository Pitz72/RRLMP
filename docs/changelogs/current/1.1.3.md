## Bug Corretti

### Recording: architettura IPC e salvataggio WAV non funzionante

Tre bug distinti impedivano il corretto funzionamento del sistema di registrazione introdotto in v1.1.1:

**Bug 1 — Type mismatch (critico):**  
`AudioRecorder.stop()` ritorna un `ArrayBuffer` in-memory, ma `useRecordingStore.stopRecording()` lo assegnava direttamente a `tempPath: string | null`. Il valore era quindi un ArrayBuffer travestito da string, rendendo ogni operazione IPC successiva impossibile.

**Bug 2 — Preload incompleto:**  
Il preload (`src/preload/index.ts`) non esponeva `convertRecording` né `deleteTempRecording`. Le chiamate `window.electron.convertRecording(...)` e `window.electron.deleteTempRecording(...)` nello store fallivano silenziosamente con `undefined is not a function`.

**Bug 3 — Argomento `format` non passato:**  
`showSaveDialogRecording` nel preload accettava solo `defaultName` (1 argomento) mentre l'IPC handler nel main si aspettava anche `format` per filtrare i tipi di file nel dialog di sistema.

**Soluzione:**
- Aggiunto IPC handler `save-recording-buffer` nel main process: salva l'ArrayBuffer su disco come file `.webm` temporaneo e ritorna il path.
- `stopRecording()` nello store ora chiama `window.electron.saveRecordingBuffer(arrayBuffer)` → ottiene il `tempPath` come stringa.
- Preload aggiornato: espone `saveRecordingBuffer`, `convertRecording`, `deleteTempRecording`, e `showSaveDialogRecording` con firma corretta (2 argomenti).

**File modificati:**
- `src/main/index.ts` — aggiunto `ipcMain.handle('save-recording-buffer', ...)`
- `src/preload/index.ts` — esposte tutte le API recording mancanti
- `src/renderer/src/store/useRecordingStore.ts` — `stopRecording` usa `saveRecordingBuffer`
