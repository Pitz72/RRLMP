# v1.9.4 — Controllo Remoto: mDNS auto-discovery del PC

**Data:** 2026-07-01

Versione **patch** (Controllo Remoto Beta, linea 1.9.x). Step 4 (ultimo del ciclo app nativa): l'app Android trova il PC in regia da sola, senza digitare l'IP.

## Cosa cambia

- **Lato PC (`src/main/RemoteControlServer.ts`)**: all'avvio il server pubblica un servizio **mDNS/DNS-SD `_rrlmp._tcp`** sulla porta 8787 (nuova dipendenza `bonjour-service`, pura JS, nessun binario nativo → nessun impatto sulla dimensione del pacchetto). Alla chiusura del server il servizio viene ritirato. **Best-effort**: se mDNS non è disponibile (es. porta 5353 già occupata su Windows da un altro Bonjour), l'errore viene solo loggato — il server resta pienamente funzionante e l'IP manuale continua a funzionare.
- **Lato app Android**: nuovo pulsante **"Cerca automaticamente il PC"** nella schermata di setup. Usa `NsdManager` per scoprire il servizio `_rrlmp._tcp`, risolve il primo trovato e precompila IP + porta. Timeout di sicurezza a 6s; se non trova nulla, resta l'inserimento manuale.
- **Wake-lock**: già presente dallo step 2 (`keepScreenOn` sulla WebView → schermo del tablet sempre acceso durante lo show).

## Test e stabilità
- Typecheck main: **0 errori**. Vitest **94/94**.
- Verifica funzionale end-to-end **14/14** con client HTTP/WebSocket reali.
- **mDNS self-discovery verificato su questa macchina Windows**: il server si annuncia e viene trovato via `bonjour-service` (`RRLMP Regia Remota :8787`).
- Build APK Android in CI da ri-verificare col nuovo codice `NsdManager` (workflow `android.yml`).

## Stato feature
Il ciclo "app nativa installabile" (step 1→4) è completo: server HTTP (1.9.1) → progetto Android (1.9.2) → build APK in CI (1.9.3) → mDNS + wake-lock (1.9.4). Da qui manca solo il **test su hardware reale** (tablet Android): installare l'APK, aprire, cercare/inserire il PC, PIN, comandare.
