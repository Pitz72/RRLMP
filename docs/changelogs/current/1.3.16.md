# v1.3.16 — Audit 2026-05-29: Blocco Types `window.electron`

**Data:** 2026-05-29

## Contesto

Allineamento dei tipi TypeScript del renderer al contratto già implementato nel preload (`src/preload/index.ts`). Gli 8 errori `tsc` residui sul renderer al termine del Blocco Cleanup (v1.3.15) erano tutti **gap dichiarativi**: handler IPC realmente esposti e funzionanti a runtime, ma assenti o ristretti nella dichiarazione di `Window.electron` in `src/renderer/src/types/index.ts`. Nessun cambio di comportamento runtime — solo tipi e zero modifiche al codice eseguito. Coerente con il principio **stabilità > funzionalità**.

Typecheck dopo i fix:
- `tsconfig.main.json` → **0 errori** (invariato)
- `tsconfig.preload.json` → **0 errori** (invariato)
- `tsconfig.json` (renderer) → **8 → 0 errori** ✅ (nuova baseline 0)

## Fix tipi (3 file)

### 1. `src/renderer/src/types/index.ts` — completa `Window.electron`
Aggiunti i 3 handler già esposti dal preload ma mai dichiarati nei tipi:
- `openExternal: (url: string) => Promise<{ success: boolean; error?: string }>` — handler IPC `open-external` (validato `isSafeExternalUrl` lato main, audit GRAVE #3 v1.3.8).
- `getPlatform: () => string` — sincrono, ritorna `process.platform` dal preload.
- `saveRecordingBuffer: (arrayBuffer: ArrayBuffer) => Promise<{ success: boolean; path?: string; error?: string }>` — handler `save-recording-buffer` (salva il buffer MediaRecorder in temp dir).

Tipi ampliati per riflettere il contratto già usato:
- `showSaveDialogRecording.format`: `'wav' | 'webm'` → `'webm' | 'wav' | 'mp3' | 'flac' | 'ogg'` (allineato all'unione di `RecordingState.exportRecording` in `useRecordingStore.ts`).
- `convertRecording.options`: aggiunto `sampleDepth?: number` (già presente nel preload `index.ts` riga 77, mai dichiarato qui).

### 2. `src/renderer/src/engine/BufferPlayer.ts` — implementa `IAudioPlayer`
`IAudioPlayer` (`AudioPlayer.interface.ts`) richiede `onIntroReached` e `onOutroReached`, assenti da `BufferPlayer`. Aggiunti come **no-op stub** coerenti con gli altri callback non supportati di questo player (`onPreEnd`, `onFadeOutStart` sono già no-op da tempo per "BufferPlayer functionality limited"). Nessun cambio funzionale: `BufferPlayer` è il fallback per il preview locale, non l'audio in onda.

### 3. `src/renderer/src/components/modals/ClipSettingsModal.tsx` — separa scelta UI da modello dati
La dropdown `transitionType` ha 4 opzioni — `default`, `crossfade`, `segue`, `gapless` — ma `TransitionType` (in `types/index.ts`) ammette solo le ultime 3. Il valore `'default'` è un sentinel UI che significa "usa il `defaultPreshowTransition` globale". Lo state era tipizzato `AudioClip['transitionType']` ma inizializzato con la stringa `'default'`, generando 2 errori `TS2345`.

Fix: introdotto type alias locale `TransitionUIChoice = TransitionType | 'default'` per lo state della modale; cast esplicito `as AudioClip['transitionType']` nel `handleSave` per **preservare al 100% il comportamento runtime corrente** (la stringa `'default'` viene persistita nel `.lmp` esattamente come prima, e `useAudioStore` la legge via `clip.transitionType ?? fallback` come sempre).

> **Nota tecnica per sessioni future** — esiste un'incongruenza latente non toccata da questo fix: quando l'utente sceglie "default" nella dropdown e salva, `clip.transitionType` resta la stringa `'default'`, non `undefined`. Tutti i lettori in `useAudioStore` (righe 409, 488, 517, 707) usano `?? fallback`, quindi con `'default'` il fallback **non scatta** e la stringa entra direttamente nello switch `'crossfade' / 'segue' / 'gapless'`, finendo nel ramo `else` (= gapless). Il risultato pratico: la voce "default" della dropdown si comporta come "gapless" anziché come "usa il default globale dalle Impostazioni". Comportamento esistente da molte versioni, mai segnalato dalla regia → non toccato per principio stabilità. Eventuale fix futuro: convertire `'default' → undefined` nel `handleSave` (1 riga), insieme a verifica regia che la voce inizi davvero a rispettare il default globale.
