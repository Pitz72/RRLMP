# Changelog v0.14.1 (2026-04-07)

## ✨ Feature Release: Waveform Editor — Marker Drag & Drop Interattivi

Questa release implementa la feature pianificata fin dalla v0.10.0 ma mai realizzata: i marker sulla waveform sono ora **trascinabili direttamente con il mouse**.

---

## 🖱️ Drag & Drop Interattivo (WaveformEditor v2)

### Problema originale
Dalla v0.10.0, il changelog prometteva "maniglie trascinabili" per Trim Start/End, Intro e Outro. L'implementazione originale basata su Wavesurfer.js non fu mai completata, e con la migrazione alla strategia Main-Side-Heavy (v0.10.7), i marker erano rimasti accessibili solo tramite pulsanti click-based ("Set Trim Start", "Set Intro", ecc.).

### Implementazione

#### 4 Handle Drag & Drop Visivi
- **Trim Start** (rosso, sinistra): handle a barra verticale sul bordo destro della zona di taglio sinistra
- **Trim End** (rosso, destra): handle sul bordo sinistro della zona di taglio destra
- **Intro** (cyan, linea verticale): handle direttamente sulla linea dell'intro marker — visibile solo se introMarker > 0
- **Outro** (arancione, linea verticale): handle sulla linea dell'outro marker — visibile solo se outroMarker > 0

#### Meccanica Drag
- `onMouseDown` sull'handle → attiva lo stato `dragging` (tipo marker)
- `document.addEventListener('mousemove')` e `'mouseup'` per tracking globale — il drag continua anche uscendo dal container
- Conversione `clientX` → secondi: `(clientX - containerRect.left) / containerRect.width * duration`
- `onChange(updates)` chiamato live durante il drag → aggiornamento visivo in tempo reale
- `stopPropagation()` nell'handle MouseDown → non triggera il seek per click

#### Pattern Anti-Stale Closure (Ref Sync)
I valori `trimStart`, `trimEnd`, `duration` e `onChange` vengono mantenuti in `useRef` e aggiornati ad ogni render. Il `useEffect` del drag dipende **solo da `dragging`**, evitando la registrazione/deregistrazione dei listener ad ogni cambio di posizione durante il drag.

```typescript
const onChangeRef   = useRef(onChange);
const trimStartRef  = useRef(trimStart);
const trimEndRef    = useRef(trimEnd);
const durationRef   = useRef(0);
// Aggiornati nel corpo del componente (inline, senza useEffect) — safe in React
onChangeRef.current  = onChange;
trimStartRef.current = trimStart;
...
```

#### Constraint Logic
- **Trim Start** non può superare `duration - trimEnd - 0.05s` (almeno 50ms di clip)
- **Trim End** non può essere tale da far iniziare prima del Trim Start

## 🎨 UX Miglioramenti

### Container Architecture
- **Outer container** (no `overflow-hidden`): cattura eventi click/drag, posiziona gli handle che possono sporgere leggermente dai bordi visivi per facilità di presa
- **Inner container** (`overflow-hidden`): clippa peaks, fill areas e linee marker

### Playhead Visivo
- Aggiunta linea bianca semitrasparente al `currentTime` durante la riproduzione — il cursore del player è ora visibile sulla waveform

### Legenda Inline
- Barra colori sopra la waveform: rosso (Trim), cyan (Intro), arancione (Outro)
- Hint testo: "Click → Seek · Trascina handle → Sposta marker"

### Ruler con punto centrale
- La ruler sotto la waveform mostra `0.00s`, la durata totale e il punto a metà `(duration/2)s`

### Cursore contestuale
- Container: `cursor-pointer` in idle, `cursor-ew-resize` durante drag attivo

### Miglioramento visivo handle
- Il grip si ingrandisce (`w-2 → w-3`) e accende il glow colorato quando attivo
- Transizione CSS `duration-75` per feedback immediato senza lag percepito
