# Changelog v0.17.0 (2026-04-10)

## Feature Release: Smart Mic — Auto-Ducking da Input Hardware

---

## Panoramica

La v0.17.0 introduce il **Smart Mic**, il sistema di auto-ducking basato su input hardware. Quando il presentatore parla nel microfono (USB, Rødecaster, Zoom LiveTrak, Focusrite, qualsiasi dispositivo di input audio standard), la musica si abbassa automaticamente esattamente come farebbe una clip voce con `duckingRole: 'source'` — senza dover premere alcun tasto.

Il sistema è **completamente opzionale**: se non armato, il comportamento del software è identico alle versioni precedenti.

---

## 1. MicManager.ts — Singleton di Monitoraggio Microfono

**File**: `src/renderer/src/engine/MicManager.ts` (nuovo)

Singleton con pattern identico a `MidiManager`. Gestisce il ciclo di vita completo del microfono:

### Architettura Audio

```
[Hardware Input: USB mic / Rødecaster / qualsiasi audioinput]
    ↓  getUserMedia({ echoCancellation: false, noiseSuppression: false })
    ↓  MediaStream
[MediaStreamAudioSourceNode]
    ↓  connect()
[AnalyserNode (fftSize=1024, smoothing=0.25)]
    ↑  getFloatTimeDomainData() ogni 40ms (~25fps)
    ↑  RMS → dBFS
[Noise Gate Logic]
    → attivazione: db > activationThresholdDb per 80ms  → isMicActive = true
    → rilascio:    db < releaseThresholdDb    per 1500ms → isMicActive = false
[activityListeners] → useAudioStore.setMicActive()
[levelListeners]    → GlobalControls VU meter
```

**Nota critica**: il nodo AnalyserNode **non è mai connesso all'output AudioContext**. Il segnale del microfono non raggiunge mai l'uscita audio — nessun rischio di feedback o echo.

Il `AudioContext` usato è quello già esistente di `AudioContextManager` (nessun contesto aggiuntivo creato).

### Noise Gate con Isteresi

```
Soglia attivazione:  -30 dBFS (configurabile via Settings)
Soglia rilascio:     -42 dBFS (fisso: activationThreshold - 12 dB)
Hold attivazione:     80ms  (evita trigger da click/consonanti brevi)
Hold rilascio:      1500ms  (evita pompa su frasi brevi o respiri)
```

L'isteresi a 12 dB tra le due soglie elimina il chattering: una volta che la musica è abbassata, rimane abbassata finché il segnale non scende significativamente sotto la soglia di attivazione.

### API Pubblica

```typescript
MicManager.getInstance().arm(deviceId?, thresholdDb?) → Promise<void>
MicManager.getInstance().disarm() → void
MicManager.getInstance().addActivityListener(cb: (active: boolean) => void) → unsubFn
MicManager.getInstance().addLevelListener(cb: (db: number) => void) → unsubFn
MicManager.getInstance().isArmed() → boolean
MicManager.getInstance().isMicSpeaking() → boolean
MicManager.getInstance().getCurrentLevel() → number (dBFS)
```

## 2. Integrazione con il Motore Audio (useAudioStore + evaluateMix)

**File**: `src/renderer/src/store/useAudioStore.ts`

### Stato aggiunto

```typescript
isMicActive: boolean  // true quando il noise gate rileva voce
```

### Variabile module-level

```typescript
let _isMicActiveGlobal = false;
```

Come `pendingCrossfadeFadeIn` e `fadingClipIds`, lo stato mic è tenuto sia nel Zustand store (per reattività UI) sia in una variabile module-level (per accesso sincrono da `evaluateMix` che è definita fuori dal `create()` callback).

### Modifica evaluateMix

```typescript
// Prima:
const isVoiceActive = activeValues.some(c => c.clip.type === 'voice');

// Dopo (v0.17.0):
const isVoiceActive = activeValues.some(c => c.clip.type === 'voice') || _isMicActiveGlobal;
```

Una singola riga. Il mic hardware viene trattato con la stessa priorità di una clip voice: quando `isMicActive` è `true`, tutte le clip con `duckingRole: 'target'` vengono abbassate al `duckingFactor` configurato nelle impostazioni.

### Azione setMicActive

```typescript
setMicActive: (active: boolean) => {
    _isMicActiveGlobal = active;
    set({ isMicActive: active });
    const { activeClips } = get();
    evaluateMix(activeClips); // re-valuta immediatamente il mix
},
```

## 3. Impostazioni (useSettingsStore)

**File**: `src/renderer/src/store/useSettingsStore.ts`

Aggiunti tre campi persistiti in localStorage:

```typescript
micInputDeviceId: string   // 'default' o deviceId specifico (default: 'default')
micThresholdDb:   number   // soglia noise gate in dBFS (default: -30)
micEnabled:       boolean  // abilitazione globale Smart Mic (default: false)
```

Nuova azione: `setMicSettings({ inputDeviceId?, thresholdDb?, enabled? })`.

`micEnabled: false` di default — il sistema è inattivo finché l'utente non lo abilita esplicitamente in Settings.

## 4. UI — Pulsante ARM e VU Meter

**File**: `src/renderer/src/components/ui/GlobalControls.tsx`

### Pulsante ARM

Posizionato nell'header, a sinistra del VU meter principale. Tre stati visivi:

| Stato | Aspetto |
|-------|---------|
| Non armato | Grigio `zinc-800`, icona `MicOff`, testo "ARM" |
| Armato — silenzio | Rosso scuro `red-900/60`, icona `Mic`, bordo `red-700` |
| Armato — voce rilevata | Rosso pieno `red-500`, glow shadow, `animate-pulse` |

### Mini VU Meter microfono

Appare solo quando il mic è armato. 8 barre verticali di altezza crescente:
- Verde (`emerald-400`): barre 0–4 (da -60 a -28 dBFS)
- Giallo (`yellow-400`): barra 5 (-22 dBFS)
- Rosso (`red-500`): barre 6–7 (-15 a -10 dBFS)
- Aggiornamento a ~25fps (ogni 40ms, sincronizzato col polling di MicManager)

### Gestione ciclo di vita React

- Arm/disarm gestito da `handleArmToggle()` — async, con guard `micArmingRef` per evitare doppio arm in StrictMode
- `useEffect` separato per i listener (level + activity) — si attiva solo quando `isArmed` diventa `true`
- `useEffect` su `micEnabled` — disarma automaticamente se l'utente disattiva il mic dalle impostazioni

## 5. UI — Settings (GeneralSettingsModal)

**File**: `src/renderer/src/components/modals/GeneralSettingsModal.tsx`

Aggiunta sezione **Smart Mic — Auto-Ducking** nel tab "Output & Mix", posizionata tra Audio Output e Mixing Intelligence:

- Toggle abilitazione (`micEnabled`)
- Dropdown dispositivo di input — mostra tutti i `audioinput` disponibili (microfoni USB, interfacce audio, Rødecaster ecc.)
- Slider soglia noise gate da -60 a -10 dBFS con anteprima soglia di rilascio (`threshold - 12 dB`)
- La sezione si opacizza (`opacity-40 pointer-events-none`) quando `micEnabled` è `false`

L'`enumerateDevices()` già chiamato all'apertura del modal ora raccoglie anche i dispositivi `audioinput` in aggiunta agli `audiooutput` esistenti.

## 6. Electron Main — Permission Handler

**File**: `src/main/index.ts`

Aggiunto `setPermissionRequestHandler` in `app.whenReady()`:

```typescript
session.defaultSession.setPermissionRequestHandler((_webContents, permission, callback) => {
    if (permission === 'media') {
        callback(true);
    } else {
        callback(false);
    }
});
```

Electron 28 richiede che il main process approvi esplicitamente le richieste `getUserMedia` dal renderer. Senza questo handler, `getUserMedia()` viene silenziosamente rifiutato anche se il sistema operativo ha i permessi microfono abilitati.

## Note Operative

- Il mic richiede permessi audio di sistema. Su Windows: Impostazioni → Privacy → Microfono → abilitare per l'app.
- Con Rødecaster Pro: ogni canale appare come device separato nel dropdown (Main Mix, Fader 1 ecc.). Selezionare "Main Mix" per il monitoraggio dell'audio del presentatore.
- Il ducking usa gli stessi parametri configurati in "Mixing Intelligence" (duckingFactor e duckingDuration) — non sono necessari parametri separati per il mic.
- La soglia di -30 dBFS è calibrata per voce parlata a distanza normale da microfono (30-50cm). Aumentare (es. -25) se ci sono troppi falsi trigger; diminuire (es. -35) se la voce non viene rilevata.
