# v1.11.2 — FX di default anche sui progetti caricati con pad vuoto

**Data:** 2026-07-02

## Contesto

Riscontro utente sulla build 1.11.0 installata: le clip audio di default apparivano solo aprendo un **nuovo** progetto; su un `.lmp` caricato bisognava chiedere il reset per farle comparire. Decisione: *"se nel salvataggio non ci sono informazioni sui pad, di default si aprono i suoni pre-caricati"*.

## Modifiche

- **`utils/defaultSfx.ts`**: `populateDefaultFxIfVirgin` → **`populateDefaultFxIfPadEmpty`**. Il vincolo "nessun `.lmp` caricato" è stato tolto: la libreria di default viene popolata **ogni volta che la colonna FX è vuota**, incluso il caricamento di un progetto salvato senza clip FX. La guardia anti-race diventa "currentFilePath INVARIATO tra prima e dopo l'IPC" (protegge dall'open-file da doppio click e dai load concorrenti; prima era "currentFilePath ancora null").
- **Call-site aggiunti dopo ogni via di load** (le tre esistenti erano solo avvio + i due "Nuovo Progetto"): handler `open-file` in `App.tsx`, `onLoadProject` della WelcomeScreen, `handleLoadProject` in `GlobalControls.tsx`.
- Dopo il popolamento `isDirty`/undo restano azzerati come prima: i default sono la vista di partenza, non una modifica (nessun prompt di salvataggio spurio). Se poi l'utente salva, le clip entrano nel `.lmp` come qualunque altra.

## Comportamento noto e accettato

Un progetto salvato deliberatamente con pad FX **vuoto** rivedrà i default alla riapertura (è esattamente la regola richiesta: pad vuoto nel salvataggio = suoni pre-caricati). Un `.lmp` con anche una sola clip FX resta intatto.
