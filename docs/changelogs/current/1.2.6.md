# v1.2.6 — Security & Engine Hardening

**Data:** 2026-05-15

## Bugfix Critici (Gravissimi)

### GR-01 — setInterval eterno nel motore audio
- **Problema**: il loop di progresso (`_syncProgress`) veniva avviato dentro il callback `create()` di Zustand senza alcun guard. In React 18 StrictMode (dev) o dopo ricariche hot, si accumulavano N interval paralleli → N×10 chiamate/secondo a Zustand.
- **Fix**: aggiunta variabile module-level `_progressLoopStarted` che garantisce un singolo interval per lifetime del modulo, indipendentemente da quante volte Zustand reinizializza il callback.
- **File**: `src/renderer/src/store/useAudioStore.ts`

### GR-02 — Race condition nel sequencer durante caricamento asincrono
- **Problema**: il sistema di guardia sulla race condition usava un contatore intero (`playGenerations`) che poteva tornare a un valore già visto se la stessa clip veniva fermata e riavviata. Con crossfade rapidi (< 500ms) il sequencer avrebbe potuto accettare un load obsoleto.
- **Fix**: sostituito il contatore con un run-ID UUID casuale (`playRunIds`). Ogni invocazione di `playClip` genera un ID univoco; il load viene accettato solo se l'ID corrisponde ancora al più recente per quella clip.
- **File**: `src/renderer/src/store/useAudioStore.ts`

### GR-03 — Nessun timeout sugli IPC handler FFmpeg
- **Problema**: `get-audio-metadata`, `get-waveform-data` e `detect-silence` non avevano alcun limite di tempo. Se FFmpeg si bloccava (file corrotto, codec sconosciuto), il renderer aspettava all'infinito causando l'hang dell'app.
- **Fix**: aggiunto `withIpcTimeout()` wrapper con `Promise.race()`. Timeout: 10s per i metadata, 30s per waveform e silence detection. In caso di timeout l'handler ritorna `{ success: false, error: 'IPC_TIMEOUT' }` invece di bloccarsi.
- **File**: `src/main/index.ts`

### GR-04 — Path traversal nel protocollo media://
- **Problema**: il handler `media://` serviva qualsiasi path assoluto senza validazione. Un path come `media:///etc/passwd` o `media:///C:/Windows/System32/config/SAM` veniva servito senza blocchi.
- **Fix**: aggiunta validazione in tre livelli prima di servire il file:
  1. `path.normalize()` per risolvere i segmenti `..`
  2. `path.isAbsolute()` per bloccare path relativi inattesi
  3. Whitelist estensioni audio (`.mp3 .wav .ogg .m4a .aac .flac .opus .wma .webm .mp4`)
- **File**: `src/main/index.ts`

## Bugfix Minori

### stopAll — stato preview non ripristinato
- **Problema**: `stopAll()` resettava `fadingClipIds` ma non `previewingClipIds`, lasciando ID orfani che avrebbero potuto impedire il corretto settaggio di `hasPlayed` nelle clip PRE-SHOW successive.
- **Fix**: aggiunto `previewingClipIds: []` nel return di `stopAll()`.
- **File**: `src/renderer/src/store/useAudioStore.ts`
