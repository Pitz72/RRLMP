# v1.4.4 — Audio Monitor nel Debug Overlay (verifica in regia)

**Data:** 2026-06-05

## Obiettivo

Rendere **osservabili e verificabili in regia** le due novità audio (Glue Multibanda v1.4.2, Omologazione Volume Clip v1.4.3) in vista del test del programma. Strumento diagnostico, **nessun impatto sul path audio**.

## Cosa cambia (`src/renderer/src/components/debug/DebugOverlay.tsx`)

Nuovo blocco **"Audio Monitor"** nel pannello sinistro del Debug Overlay (hotkey **Ctrl+Shift+D**), con readout aggiornato live (polling 100 ms **solo a overlay aperto**, fermato alla chiusura):

- **Glue Multibanda GR**: gain reduction corrente del compressore multibanda (massimo tra le 3 bande, via `getCompressorReduction`). Negativo = sta lavorando; ~0 = gentile/inattivo. Permette di confermare che il glue è davvero leggero.
- **Limiter GR**: gain reduction del limiter brickwall (via `getLimiterReduction`). Se resta ~0 in onda, il segnale non sta saturando il limiter.
- **Omologazione**: stato ON/OFF + target LUFS corrente.
- **Per ogni clip in onda**: loudness misurata (LUFS) → guadagno di omologazione applicato (clamp ±9 dB), oppure "non misurata" se la misura EBU R128 non è ancora pronta.

## Note tecniche

- Sfrutta `AudioContextManager.getCompressorReduction()` / `getLimiterReduction()` (già esistenti ma finora non consumati dalla UI).
- Hook (`useState`/`useEffect`) aggiunti prima dell'early-return per rispettare le regole degli hook; l'intervallo parte solo con overlay visibile e viene ripulito alla chiusura.
- Il guadagno di omologazione è ricalcolato in lettura (stessa formula di `computeLoudnessGain`: `target − LUFS`, clamp ±9 dB) senza toccare il motore.
