# v1.15.8 — Fix auto-updater (note di rilascio HTML, chiusura pulita a install)

**Data:** 2026-07-04

## Contesto

Due bug emersi dal primo test dal vivo dell'auto-updater su Windows (release v1.15.7).

## UpdateModal

- **Note di rilascio mostrate come testo HTML grezzo** (`<h2>...</h2><p>...</p>` visibili letteralmente): le note arrivano già renderizzate in HTML da GitHub — via feed Atom di `electron-updater` sul percorso nativo (Windows/Linux AppImage), via `body_html` dell'API REST sul fallback (macOS/.deb) — ma venivano interpolate come stringa invece che renderizzate. Ora `UpdateModal` le renderizza come HTML (contenuto fidato: proviene solo dal corpo release pubblicato da `.github/workflows/build.yml`), con stile scuro dedicato per titoli/tabelle/blockquote in `spectrum.css`.
- **`updateManager.ts`**: il fallback macOS/.deb ora richiede l'header `Accept: application/vnd.github.html+json` per ottenere `body_html`, uniformando il formato delle note di rilascio su tutte le piattaforme.

## Chiusura app durante l'installazione

- **Bug**: cliccando "Riavvia e installa", `quitAndInstall()` di `electron-updater` lancia già l'installer PRIMA di chiudere l'app (`BaseUpdater.install` poi `app.quit()`); il nostro handshake di chiusura (richiesta salvataggio se `isDirty`) intercettava comunque quell'evento, mostrando l'app ancora aperta con un prompt di salvataggio sotto la finestra dell'installer — confuso e ridondante dopo che l'utente aveva già confermato il riavvio.
- **Fix**: nuovo flag `quittingForUpdate` in `src/main/index.ts`, impostato prima di chiamare `quitAndInstall()`; l'handler `close` della finestra lo controlla e lascia chiudere senza handshake in quel solo caso.
