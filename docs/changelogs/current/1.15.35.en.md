# v1.15.35 — Code review: a safer live desk

**Type:** fixes (no new features) · **Date:** 2026-10-28

Full code review of 1.15.34. Found and fixed: 1 critical issue, 4 serious, 4 medium and 10 minor. Technical details are in `docs/technical/REVISIONE-CODICE-2026-10-28.md` (Italian).

## Ctrl+R no longer reloads the interface

The program had no menu of its own, so Electron's stock menu stayed active: hidden, but with working shortcuts. **Ctrl+R** and **Ctrl+Shift+R** reloaded the interface like a browser. On air that meant instant silence, the unsaved project lost, the microphone disarmed and the running recording lost. Ctrl+Shift+I (developer tools) and Ctrl +/− zoom were active too.

In the installed program that menu is now gone. Copy and paste in text fields work as before.

## MIDI controllers work again

The permission handler denied MIDI access together with every other permission the program does not need. Since 0.17.0 a connected controller was never seen: no launching from pads, no MIDI Learn, no global commands (STOP ALL, master volume). The MIDI Simulator (Ctrl+Shift+M) does not go through that path and hid the problem.

MIDI access is now allowed. SysEx, which the program does not use, stays denied.

## The recording is no longer lost when quitting

The session recording stays in memory until you stop it, then in a temporary file until you export it. Quitting the program, or choosing «Restart and install» for an update, lost it without a warning. The program now asks for confirmation when a recording is running or has not been exported yet.

## Exporting no longer overwrites the archive

With «Export project with audio» the `audio/` archive becomes the reference for your clips, and the original files can be deleted. If a new clip had the same file name as an archived one and came earlier in the running order, it took that name and **overwrote the archived copy**: that clip's audio was lost, possibly with the original already gone. Files already in the archive now keep their names and new clips get a suffix (`intro_1.mp3`). The same source used by several clips is copied only once.

## A clip that cannot play no longer stops the chain

When a file could not be played (for example a `.wma`, which the program accepts and analyses but the playback engine cannot decode, or a damaged file), three things happened:

- in an automatic sequence (PRE-SHOW, `play_next` tracks) the chain stopped there and left silence;
- nothing appeared on screen;
- the next click on the same clip was taken as «cancel loading» and ignored.

Now a message with the clip name appears, the sequence moves on to the next clip, and the next click really tries again.

## Other fixes

- **JINGLE and PROMO:** files dropped into these columns never got their duration. On air the banner showed a blinking red −00:00 for the whole jingle. The duration is now read, and clips already in a project repair themselves the first time they play.
- **Double-clicking a `.lmp` while on air:** with a saved project it stopped everything without asking. With audio on air it now asks for confirmation.
- **Ctrl+Z, Ctrl+Y, Alt+F4:** they also fired the jingle bound to Z or Y, or the F4 column. Combinations with Ctrl, Alt or Cmd no longer launch clips.
- **On-air performance:** while something played, every card on the board and the toolbar redrew 10 times a second. Measured on 14 cards: from 560 to 40 redraws in two seconds. Only the card on air updates now. The state sent to the remote-control tablet also goes out only when something changes.
- **MIDI Learn:** global commands and the Keyboard/MIDI window could only be learned from channel 1. All 16 channels work now, as they already did for launching.
- **Microphone ARM:** if the microphone is not available, a message now tells you why. Before, the button just stayed off.
- **FX pad:** the «Restore» messages were in Italian even with the program in English.
- **Opening a `.lmp`:** a file with a column without clips was rejected as «corrupted» with a technical error. It now reaches the validity check, which explains what is wrong.
- **Autosave:** with the `.lmp` moved or on an unplugged USB stick, autosaves piled up without limit. The 10-copy rotation now always applies.
- **Remote control:** the tablet connection must come from the same address as the page. Before, the 8787 port was enough.

## For developers

- New pure module `src/main/archivePlan.ts` (export naming plan), with tests.
- `will-navigate` blocked in production: the window cannot leave its own page.
- The IPC channels `start-recording`, `append-record-chunk` and `stop-recording` are not exposed by the preload and are not used: the 1.15.21 field check concerns an inactive path.
- Typecheck 0 errors on 4 projects, Vitest 265/265 (+19), `vite build` completed.
