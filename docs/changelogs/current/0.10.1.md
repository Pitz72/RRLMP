# Changelog v0.10.1 (2026-04-05)

## 🚑 Hotfix Release
Questa è una patch di emergenza per risolvere problemi critici di caricamento delle funzionalità introdotte nella versione 0.10.0, causati da policy di sicurezza troppo restrittive.

## 🛠️ Fix Tecnici (Content Security Policy)

### 📡 Sblocco Fetch su Protocollo Custom
- **Problema:** L'editor della Waveform (basato su `wavesurfer.js`) non riusciva a caricare e disegnare le clip audio. Questo accadeva perché la libreria esegue chiamate `fetch()` interne per ottenere l'audio, ma il protocollo locale `media://` era bloccato dalle policy di rete (CSP `connect-src`).
- **Soluzione:** Aggiornato l'header `Content-Security-Policy` del processo principale per autorizzare esplicitamente la connessione dati (`connect-src`) verso il protocollo `media:`, permettendo all'editor visivo di accedere liberamente ai file PCM ad alta velocità.

### 🔄 Sblocco Check Aggiornamenti
- **Problema:** Il controllo versione falliva con un errore `TypeError: Failed to fetch`. La policy permetteva connessioni solo verso `https://www.runtimeradio.it`, bloccando le chiamate API verso il root domain (senza "www").
- **Soluzione:** Aggiunto il dominio base `https://runtimeradio.it` alla whitelist della CSP.

---

## ⚠️ Nota di Revisione (aggiornata in v0.10.7)

Il fix "Sblocco Fetch su Protocollo Custom" fu originariamente pensato per permettere a `wavesurfer.js` di accedere al protocollo `media://`. La libreria Wavesurfer è stata **abbandonata tra v0.10.2 e v0.10.7** in favore di un engine custom (FFmpeg peaks via IPC + `<audio>` HTML5).

La modifica CSP (`connect-src media:`) è tuttavia **ancora valida e necessaria**: il protocollo `media://` è utilizzato dal tag `<audio>` HTML5 del player di riproduzione. Il fix documentato rimane corretto nei suoi effetti, ma il contesto tecnico originale (wavesurfer.js) è obsoleto.
