# v1.3.18 — Fix: colonna SHOW ASSETS rifiutava i file trascinati dall'OS

**Data:** 2026-06-05

## Sintomo (segnalato in regia)

Trascinando un file audio **dall'Esplora risorse** sulla colonna **SHOW ASSETS**:
- si vedeva l'indicatore di posizionamento durante il drag;
- al rilascio la clip **spariva** (nessuna clip creata) → sembrava "persa".

Lo stesso file su un'altra colonna (es. VOCI) veniva caricato correttamente; e una clip già esistente **spostata** verso assets si spostava mantenendo le proprietà. Quindi il problema era specifico del **drop nativo di file esterni** sulla colonna assets.

## Causa

La colonna assets aveva `isLocked: true` hardcoded in `DEFAULT_COLUMNS` (`useProjectStore.ts`). Il fix **DND-04 (v1.3.4)** aveva introdotto in `MainGrid.handleNativeDrop` un guard che **rifiuta il drop nativo** sulle colonne `isLocked`. Conseguenze:
- il drop su assets veniva scartato silenziosamente (`return` senza creare la clip);
- `handleNativeDragOver` **non** controllava `isLocked`, quindi l'indicatore di posizionamento appariva comunque → falsa impressione che il drop sarebbe andato a buon fine;
- lo spostamento interno (dnd-kit `moveClip`) non controlla il lock della destinazione → funzionava (ecco perché spostare una clip *dentro* assets riusciva).
- **non esiste alcuna UI** per sbloccare la colonna (nessuna azione `toggleLock` nello store, nessun lucchetto nell'header) → assets era bloccata in modo permanente.

Prima di v1.3.4 il drop nativo **ignorava** `isLocked`: si potevano trascinare file in assets. La v1.3.4 ha quindi introdotto una **regressione** dal punto di vista dell'operatore, che usa assets proprio per i jingle.

## Fix

Per richiesta esplicita: **la colonna SHOW ASSETS deve accettare i file trascinati esattamente come tutte le altre colonne** (comportamento pre-v1.3.4).

1. **`MainGrid.tsx`** — rimosso il guard `if (targetCol?.isLocked) return` in `handleNativeDrop`. Il drop nativo non è più bloccato da `isLocked`. La rimozione del guard (anziché il solo cambio di default) è necessaria per coprire anche i **progetti `.lmp` già salvati** con `assets isLocked:true`: `validateLmpProjectData` non normalizza `isLocked`, quindi all'apertura il flag persiste.
2. **`useProjectStore.ts`** — `DEFAULT_COLUMNS` colonna assets `isLocked: true → false` (progetti nuovi puliti).

Il campo `isLocked` resta nel modello dati (`types/index.ts`) per eventuale uso futuro, ma non blocca più nulla a runtime (nessuna UI lo attiva, nessuna colonna lo usa più). L'indicatore di drag-over ora è coerente: tutte le colonne accettano il drop.

## Nota per sviluppo futuro (collegata)

L'utente ha proposto di separare i jingle dalla colonna assets in una colonna dedicata **"Jingle&Promo"** (regole jingle di default: la colonna `asset` dà già `nextAction:'stop'`, `behavior:'normal'`, `duckingRole:'none'`, `fadeOut:500ms`) e una **regola di rotazione su PRE-SHOW** in stile AzuraCast ("riproduci una volta ogni X brani", intervallo continuo; jingle/promo parte a fine brano seguendo le regole di transizione, mai sovrapposto). Da progettare a parte: cambiamenti strutturali (nuove colonne + motore di scheduling PRE-SHOW).
