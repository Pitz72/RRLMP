# v0.5.5 - Fix Finale Loop 🔁

**Data:** 30 Gennaio 2026
**Stato:** Maintenance Release

## Problema Risolto
*   **Loop Silenzioso (Ghost Loop):** Risolto un bug dove le clip in loop, pur ripetendosi correttamente, diventavano silenziose dopo il primo passaggio.
    *   **Causa:** Il sistema attivava erroneamente il *Fade Out* alla fine del primo ciclo, abbassando il volume a 0 e lasciandolo lì.
    *   **Fix:** Il *Fade Out* automatico e il trigger *Pre-End* (che lancia la clip successiva) sono ora disabilitati se la clip è impostata in modalità Loop.

# v0.5.4 - Native Rollback 🔙

**Data:** 30 Gennaio 2026
**Stato:** Emergency Fix

## Modifica Architetturale
Abbiamo ripristinato l'uso del protocollo nativo `file://` di Chromium.

*   **Perché:** Il protocollo custom `media://` si è rivelato instabile con alcuni formati audio (WAV) e percorsi complessi, causando errori di decodifica (`DEMUXER_ERROR`).
*   **Risultato:** Il player ora accede ai file direttamente dal disco come farebbe un browser standard. Questo garantisce la massima compatibilità con tutti i formati supportati da Chrome (MP3, WAV, OGG, AAC, FLAC) e risolve ogni problema di buffering o parsing.

## File Modificati
*   `src/renderer/src/utils/pathUtils.ts` (Switch to file://)
*   `package.json` (v0.5.4)

# v0.5.3 - Fix Decoding Percorsi 🛣️

**Data:** 2026-01-30
**Stato:** Hotfix Urgente

## Problema Risolto
*   **Audio con Spazi/Caratteri Speciali:** Risolto definitivamente l'errore `DEMUXER_ERROR_COULD_NOT_OPEN` che si verificava quando il percorso del file conteneva spazi (es. `JINGLE UMBERTO.wav`) o caratteri speciali.
    *   **Causa:** Il protocollo `media://` non decodificava correttamente l'URL ricevuto dal player (es. `%20` non veniva convertito in spazio), rendendo il percorso illeggibile per il sistema operativo.
    *   **Soluzione:** Implementata una logica rigorosa di *Decoding URI* e sanitizzazione del percorso nel Main Process, garantendo la compatibilità con percorsi Windows complessi.

## File Modificati
*   `src/main/index.ts` (URI Decoding Fix)
*   `package.json` (v0.5.3)

# v0.5.2 - WAV Fix 📝

**Data:** 2026-01-30
**Stato:** Hotfix

## Problema Risolto
*   **Supporto File WAV:** Risolto un errore (`DEMUXER_ERROR_COULD_NOT_OPEN`) che impediva la riproduzione di file `.wav` (e altri formati non-MP3).
    *   **Causa:** Il server interno dichiarava erroneamente tutti i file come `audio/mpeg`.
    *   **Soluzione:** Il sistema ora identifica correttamente il formato (`audio/wav`, `audio/ogg`, `audio/mp4`, `audio/flac`) permettendo al motore audio di decodificarli correttamente.

## File Modificati
*   `src/main/index.ts` (Dynamic Content-Type logic)

# v0.5.0 - Global Hotkeys 🎹

**Data:** 2026-01-30
**Stato:** Feature Release

## Obiettivo
Implementare il controllo da tastiera per le funzioni di regia (Play/Stop), aumentando la velocità operativa e l'accessibilità.

## Nuove Funzionalità

### Tasti Funzione (F1 - F5)
Ogni tasto attiva la riproduzione intelligente per una colonna specifica:
*   **F1:** Colonna 1 (Assets)
*   **F2:** Colonna 2 (Music)
*   **F3:** Colonna 3 (Voice)
*   **F4:** Colonna 4 (SFX)
*   **F5:** Colonna 5 (Pre-Show)

**Smart Logic:**
*   Il comando cerca la **prima clip libera** (che non è in riproduzione).
*   Se nessuna clip sta suonando, lancia la prima della lista.
*   Se una clip sta suonando, lancia la successiva disponibile.

### Panic Button (ESC)
*   **ESC:** Ferma immediatamente tutte le riproduzioni attive (`STOP ALL`).

### Safety Guards
I comandi vengono automaticamente ignorati se:
*   L'utente sta scrivendo in un campo di testo (es. rinominando una clip).
*   Un modale (es. Impostazioni Clip) è aperto.

## Dettagli Tecnici
*   **Store:** Aggiornato `useAudioStore` con l'azione `playColumn(index)`.
*   **Listeners:** Implementato `Global Key Listener` in `MainGrid.tsx`.
*   **Guards:** Controllo su `document.activeElement` e stato `editingClip`.

*   `src/renderer/src/store/useAudioStore.ts`
*   `src/renderer/src/components/layout/MainGrid.tsx`
*   `package.json` (v0.5.0)
