# Changelog v0.9.17 (2026-04-05)

## 🎯 Obiettivi della Release
Questa release si focalizza sulla robustezza tecnica del software, risolvendo criticità gravi identificate nella roadmap riguardanti la type safety, la coerenza dell'architettura audio e la conformità delle interfacce dei player.

## 🛠️ Fix & Miglioramenti Tecnici

### 🔴 Core Audio & Graph (GR2, M4)
- **Ottimizzazione Topologia Audio (GR2)**: Riorganizzato e documentato esplicitamente il grafo audio globale. Il `masterGain` funge ora da nodo centrale unico che instrada il segnale sia alla `destination` (output fisico) che allo `splitter` per l'analisi stereo, eliminando potenziali ambiguità di fase o sdoppiamenti del segnale.
- **Performance VU Meter (M4)**: Ridotto il `fftSize` degli analyser L/R da 256 a 64. Questa ottimizzazione riduce il carico computazionale del DSP per il calcolo dei livelli RMS/Peak, mantenendo una precisione visiva eccellente per la regia.

### 🟠 Player Engine (GR11)
- **Conformità Interfaccia BufferPlayer**: Implementato il metodo `setOutputDevice` in `BufferPlayer.ts`. Sebbene l'API Web Audio non supporti il re-routing nativo di singoli nodi buffer su device diversi (richiederebbe contesti separati), l'implementazione del metodo come no-op previene crash a runtime durante il cambio globale di output nelle impostazioni.

### 🔵 Type Safety & Hardening (GR4)
- **Eliminazione `any` e `@ts-ignore`**: 
    - Tipizzata l'interfaccia `IAudioPlayer` e le sue implementazioni (`StreamPlayer`, `BufferPlayer`) utilizzando l'interfaccia `AudioClip` al posto di `any`.
    - Risolta la soppressione degli errori su `setSinkId` in `StreamPlayer` tramite una local interface dedicata `HTMLAudioElementWithSinkId`.
    - Tipizzato integralmente il `MidiManager.ts` introducendo interfacce locali per le Web MIDI API (`MidiAccess`, `MidiPort`, `MidiEvent`), eliminando la dipendenza da `any` per la gestione dei controller esterni.
    - Bonificato il file di `preload/index.ts` utilizzando i tipi ufficiali di Electron (`IpcRendererEvent`, `webUtils`) per le API esposte al renderer.

## 📈 Stato del Progetto
Con questa release, la copertura delle criticità "Gravi" sale al **100%**, portando il software in una condizione di stabilità ideale per il testing finale pre-v1.0.0.
