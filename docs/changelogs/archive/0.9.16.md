# Changelog v0.9.16

*Data: 2026-04-05*

## 💬 UX — Dialog, MIDI Status e MIDI Learn

### [M1] Dialog di chiusura con stringhe localizzate (i18n)

**File modificati**:
- `src/main/index.ts` — nuovo handler `show-close-dialog-i18n`
- `src/preload/index.ts` — esposto `showCloseDialogI18n` via contextBridge
- `src/renderer/src/App.tsx` — `handleCloseIntent` usa ora il dialog i18n

**Problema**:
Il dialog nativo "Modifiche non salvate?" mostrava sempre i tasti `Salva / Non Salvare / Annulla`
in italiano, indipendentemente dalla lingua selezionata nell'interfaccia.
I dialog nativi (Electron `dialog.showMessageBox`) vengono generati nel main process,
che non ha accesso al contesto i18next del renderer.

**Soluzione**:
Aggiunto un nuovo handler IPC `show-close-dialog-i18n` che accetta le label
come parametro invece di usare stringhe hardcoded:

```typescript
ipcMain.handle('show-close-dialog-i18n', async (_, labels) => {
    return dialog.showMessageBox(mainWindow, {
        buttons: [labels.btnSave, labels.btnDiscard, labels.btnCancel],
        title: labels.title,
        message: labels.message,
        ...
    });
});
```

Il renderer legge le traduzioni tramite `import('i18next')` dinamico
e le passa al main process. Se `showCloseDialogI18n` non è disponibile
(preload vecchio, ambiente test), cade in fallback sul vecchio handler legacy.

### [M2] Notifica visiva quando MIDI non è disponibile

**File modificati**:
- `src/renderer/src/engine/MidiManager.ts` — sistema `addStatusListener` + `MidiStatusCallback`
- `src/renderer/src/components/ui/GlobalControls.tsx` — badge MIDI sul pulsante

**Problema**:
Se `navigator.requestMIDIAccess()` falliva (sistema non supporta MIDI, permesso negato,
nessun driver), l'errore finiva solo in `console.error()`. L'utente non riceveva
nessun feedback — il tasto MIDI nell'interfaccia sembrava funzionante ma era inutile.

**Soluzione**:
`MidiManager` espone ora `addStatusListener(callback)` che notifica gli subscriber con
`(supported: boolean, inputCount: number)` al termine dell'inizializzazione
(e ad ogni cambio di stato input).

Nel badge del tasto MIDI in `GlobalControls`:
- ✅ **MIDI funzionante + controller connessi**: badge verde con il numero di input (es. `MIDI 2`)
- ✅ **MIDI funzionante ma 0 controller**: tasto normale senza badge
- ❌ **MIDI non supportato / errore**: tasto rosso con simbolo `✕` e tooltip "MIDI non disponibile"
- Viene scritto un log `⚠️` nel debug overlay (Ctrl+Shift+D)

### [M3] MIDI Learn: timeout automatico 15s + uscita con Escape

**File modificato**: `src/renderer/src/components/ui/GlobalControls.tsx`

**Problema**:
Premendo il tasto MIDI per avviare la modalità Learn, il software rimaneva in
attesa di un segnale MIDI indefinitamente. Se l'operatore dimenticava di premere
un tasto sul controller (o il controller non era connesso), la modalità Learn
restava attiva per tutta la sessione, alterando il comportamento di click e fader.

**Soluzione**:
Due meccanismi di uscita automatica:

1. **Timeout** — `useEffect` con `setInterval` decreta. Dopo 15 secondi di learn attivo
   senza input ricevuto, la modalità viene disattivata automaticamente e viene scritto
   un log nel debug overlay.

2. **Escape** — listener `keydown` che, se `key === 'Escape'` durante MIDI Learn,
   resetta immediatamente la modalità e annulla il `pendingBind`.

3. **Countdown visivo** — badge `{N}s` appare sull'angolo superiore del tasto MIDI
   durante il countdown, mostrando i secondi rimanenti prima del timeout automatico.

```
[MIDI 2]    ← badge verde: 2 controller connessi
[MIDI ✕]    ← rosso: MIDI non disponibile
[MIDI]      ← normale: pronto ma 0 controller
[ 12s ]     ← durante learn mode: countdown
```
