# Changelog v0.12.3 (2026-04-06)

## ✨ Novità

- **LMP Integrity Check**: Aggiunta la diagnostica di integrità file al caricamento dei progetti `.lmp`. Le clip il cui file audio non è più presente fisicamente sul disco verranno ora evidenziate visivamente di rosso con l'avviso "⚠️ File Non Trovato", prevenendo crash o playback silenziosi durante la diretta.
- **Miglioramento Mini-Editor Waveform**: La densità visiva (Peak Height) delle forme d'onda è stata amplificata (moltiplicatore x2.0) a livello di motore FFmpeg nel Main Process. Questo permette di visualizzare molto più chiaramente i transienti e i picchi anche in file esportati con Master di volume molto basso o normalizzazione pregressa assente.

## 🐛 Fix Tecnici

- Le clip mancanti non bloccano più il parsing intero del progetto ma vengono gestite *gracefully* con uno status dedicato `isMissing`.

# Changelog v0.12.1 (2026-04-06)

## 🐛 HOTFIX: Waveform Rendering e Outro Pre-Cue
Risultati del field-test per completare l'esperienza visiva dello speaker e stabilizzare la UI del WaveformEditor.

### Componenti Modificati
- **Main Process (`AudioProcessor.ts`)**: Corretto silente DOM Overload. Il downsampling a 100hz generava ancora troppi dati (fino a 60,000 floats per clip lunghe). Quando React riceveva l'array di peak, tentava di renderizzare decine di migliaia di nodi `<div flex-1>`, spingendo il browser engine a schiacciarli a "0 pixel" (rendendoli invisibili) o crashando del tutto. Abbiamo introdotto un limitatore fisso (`TARGET_BARS = 200`) garantendo che il frontend non debba mai fare rendering su più di 200 istanze DOM per file, a prescindere dalla durata. Ora la Waveform è solida e tangibile.
- **Renderer (`ClipCard.tsx`)**: Esteso il feedback real-time della board all'**Outro**. Aggiunto lo stato `inOutroPre` che, a 15 secondi dall'outro marker, genera il countdown testuale intelligente (`OUTRO IN: -Xs`) proprio come avviene per l'intro. L'allarme `🚨 OUTRO` rosso scatta unicamente nell'esatto momento del superamento soglia.

# Changelog v0.12.0 (2026-04-06)

## ✨ UI/UX Polish & Architettura Cues
Affinamento estetico e prestazionale dello chassis e della latenza del player, su richiesta del dipartimento Speaker.

### 🚀 Novità Frontend
- **Main Board Real-Time Cues**: Introdotto un sistema di "Semafori Testuali" attivi all'apice inferiore destro delle Clip in riproduzione nella grid (`ClipCard.tsx`).
  - Durante un'Intro in riproduzione, appare un contatore azzurro dinamico del tipo `INTRO: -04s` che esegue un conto alla rovescia reale dei millisecondi mancanti dal marker intro, informando lo speaker per le battute.
  - Al termine della Clip, qualora sia impostato l'outro marker, subentra l'etichetta `🚨 OUTRO` arancione statico, per dare il via alla narrazione di chiusura sopra il mix out.

### 🛠️ Ottimizzazioni Backend
- **Stream Hybrid Buffer (Latenza Zero)**: Il lettore Media Stream proxy di NodeJS avviava pacchetti I/O massicci da `1MB`. Ridotta a `128KB` la soglia iniziale del Range request (0-) per garantire al tag `<audio>` un caricamento istantaneo del suono senza colli di bottiglia, mantenendo invece l'`1MB` in corsa per la parallela stabilità asincrona contro i NAS.
- **FFmpeg 100Hz Waveform Array Safety**: Ricostruito l'engine estrattivo PCM Peaks limitando l'algoritmo di astats a `100hz` costanti da `8000Hz`, dimezzando il carico della RAM in Node. Inserita protezione modulare contro lo slicing difettoso (Buffer dispari) risolvendo il problema della stesura vuota / bug rendering del tracciato nell'editor di Taglio.
